# 一颗星的两次审查

把两次审查记在同一知识点的审查记录里。页首写明知识点 ID、issue、PR、设计者、实现者和两次审查的执行者。每位执行者写实际模型及可区分的会话或代理名。每次记录所审设计或代码的提交号；在同一 PR 里能找到审查时的版本、要求修改的事项、复核证据和结论。

## 交给实现者以前

由未参与设计的人读任务说明、知识点卡和五道挑战，按 [七问](../SKILL.md#检查) 在纸面上走一遍。试着直接用脚本扮演领航员，按用例画出关键两帧。依次指出：

1. 哪些线索在猜之前可见？把揭晓遮住，转折还能从哪两个物件上看出来？
2. 孩子在哪一步有两个真实可选的做法？画出两种走法留下的作品，比较哪一笔能反映他的选择。下一站增加了什么发现？
3. 按实际题面复算数字、末题和适用条件。列出至少三种错误想法，各举一个回答，看提示和纠错能否各帮一步。
4. 哪些屏幕还需要实现者替设计者出题、写台词或猜摆法？逐处退回原稿补全。

记录「通过」或「退回」及理由。核对修订稿后再派实现者。科学验收者据此固定数值算例和可观察的用例，保存初次失败的结果。

## 实物做完以后

由未参与设计和实现的人按真实入口玩一遍。另走一条孩子可以选的路线，分别做完挑战。用手机深色、平板和桌面看到的实物回答 [七问](../SKILL.md#检查)；逐题写出看见了什么，附题号、动作、读数或截图。特别保留以下证据：

- 开场与转折图。遮住揭晓，写明两帧的可见差别。另核算所用数字及其来源。
- 两次选择与对应的成品图。指出哪一笔由哪一步选择产生；走查也要比较实际绘出的形状或位置。
- 探索中出现过的读数和挑战末题。说明末题新增的判断及其反馈。
- 手机、平板、桌面截图。放大看把手、零件、文字能否分别看清。给出可打开的截图路径或本次 CI 截图产物的链接与文件名。

保留原有科学与契约检查，包括猜错后的反馈、触摸与键盘、减少动效、重玩、消息次数、沙箱和数值边界。实际游玩中的惊讶与乐趣最后由 Luka 和舰长判断。阻断和重要问题逐条修订，再用同一个用例复核。将审查记录和具体试玩入口放入这颗星的 PR。
