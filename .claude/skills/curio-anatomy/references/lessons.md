# 经验清单

做「生命的说明书」三个模拟模块时踩过的坑和定下的做法。写提示词时把「实现」一节原样贴进第 7 节；审查时逐条对照。发现新坑就补在对应的节里，写清楚是哪个模块遇到的。

## 为什么上一版没意思（2026-11-06 复盘）

Kimi 照提示词做的讲解事实都对，孩子做完却没有乐趣、没有成就感。原因主要在提示词和规格，不在实现者：

1. 形式被定死成「一句话 + 静态图 + 选择题」，等于会说话的幻灯片；规格里本来就有能动手的模拟模块，没用。
2. 提示词全是「不许」：字数、词表、不能说的话。一句也没提怎么让孩子惊讶、怎么让他有成就感。
3. 知识拆成了事实清单，不是谜题；挑战考的是「刚才讲了什么」。
4. 图少，而且都是静态的。

## 设计

- 先写谜题、真相表、一句话实物、零件清单、站点，再写代码。设计说明用 `brief-template.md`。
- 每站换一种动作：转、拖、按住、点、配对。四站都是「按住」就成了另一种「点继续」。
- 先问再揭晓。提问前，颜色、标签、位置都不能泄露答案（染色体第 4 站：先问 Y 来自谁，回答后才给 X、Y 上色）。
- 核对事实时会发现直觉是错的，要按真相改设计。例：DNA 的体积远小于细胞核，真正的难题不是「装不下」，而是不打结、找得到、分得开，所以预测题的选项是「剪成小段」「揉成一团」「一圈圈绕好」。
- 「哇」的数字要从 MODEL 算出来，换算到孩子的世界：乒乓球、走路几个小时、一秒念一个字。
- 反直觉的事实是很好的钩子（21 号染色体比 22 号还小）。
- 星卡用孩子这一趟亲手做出来的东西（他排好的染色体图），不是一个分数。
- 涉及「如果……」的算术（2⁴⁵ ≈ 35 万亿）要说明是假设，不要说身体就是这样长的。
- 前后几站的说法不能互相打架。染色体模块第 1 站说「剪成小段，说明书就不全了」，第 3 站却出现 46 根分开的短棒，孩子会以为「还是剪了」。为了好画做了简化（只画了一根线），就要明说：「说明书本来就分成 46 卷，每卷是完整的一根；刚才为了看得清，只画了一根。」
- 这颗星的核心词要在动手时说出名字（「这样卷好的小短棒，就叫染色体」），不要等到最后一站才第一次出现。
- 「哇」要画出来，不能只是一句话。「13 公里，要走 3 小时」画成一条路、三个小时的刻度和一个走路的小人。
- 先问再揭晓也包括**画面**：提问前不要把答案摆在画面上。DNA 模块第 2 站问「是不是同一本书」之前，书、拨盘、亮起的行已经全摆好了；第 3 站提问前身体上已有四个圆圈。提问前只画问题需要的东西，回答后再摆出实物。
- 「一样」要有画面上的证据：要说明「同一本书」，就放一本固定不动的书（封面、厚度）做参照，变的只有书签和亮起的几处。孩子用眼睛判断，不听领航员的一句话。
- 为画面编的示意数字（「第 388512 页」）不能当成事实出现在读数和星卡上。要么不显示，要么写明「如果……」。真实规律不连续的地方，也不要画成连续的（细胞读的是散在书里的很多小段，不是一段连续的页）。
- 「哇」要落到孩子能感受到的尺度：「念完要 200 年」画成一排「一辈子」（按 80 年，2024 年我国人均预期寿命约 79 岁），「要念 2 个半辈子」；对数刻度尺 8 岁孩子读不懂。
- 画「没有」的东西时，别画出像它的形状：红细胞中间的凹陷不要用实心圆（深色模式下像细胞核），用一圈细线或两道弧线。
- 样本要真：手背最外层是死细胞，不能画成带核的活细胞；学校实验用的口腔上皮细胞更合适。倍数约定下看不清的，就换停的倍数（细胞模块第 1 站停在 100 倍，400 倍留给血），不要硬凑规格里的数字。
- 演示要和说法一致：「比 0.1 毫米小，眼睛就看不见」，可画面上 0.07 毫米的头发明明看得见。说法改成「又小、又挤在一起，眼睛就分不清」。
- 倍数、尺寸为了画面做了约定（视野宽度），要对孩子说明「这是飞船上的简化」；把人画进显微镜圆圈时，要有「缩小」的过渡。
- 性别、遗传相关的说法加「一般」（「男孩的第 23 对一般是 X 和 Y」）。

## 实现

1. 所有数字来自页面里的一个 `MODEL` 对象，每个值旁边写出处注释。画面、读数、领航员的话都从它算。
2. 孩子推到的进度 `t` 和画面上缓动跟随的进度 `p` 分开；读数和画面用 `p`。
3. 进度到 98.5% 就算完成（`fin()`），同时把 `t`、`p` 都设成 1，读数对齐到 MODEL 的终值。不然会出现读数已经四舍五入成「1 万倍」，却迟迟不触发完成；或者领航员说「13 米」，读数显示「14 米」。
4. 按住类按钮：`pointerdown` 时 `setPointerCapture`，`pointerup`、`pointercancel`、`lostpointercapture` 都要松开；完成时把 `S.hold` 设成 false；屏蔽长按菜单。
5. 每个动手操作都要有键盘替代：方向键、空格、回车推进同一个 `t`。
6. `prefers-reduced-motion`：缓动系数取 1（直接到位），自动播放的计数和飞入也直接到位，但内容一步不少。
7. 可点的东西互不重叠：每个放置时试几百个候选位置，挑离别人最远的那个；点击判定用到线段的距离，半径至少 26 个 viewBox 单位。
8. SVG 里的字少而大，至少 15 个 viewBox 单位。手机上 800 宽的 viewBox 会缩到不到一半，13 单位的字只剩 6 像素；重要的话放在 SVG 外的领航员气泡和读数里。
9. 颜色全用 CSS 变量（包括 SVG 里的 fill 和 stroke），深色模式自己截图看一遍。
10. 单文件，不联网、不读写存储、不用外部字体和库；先发 `ready`，结束发 `complete`；用到的 verb 都写进 manifest 的 `emits`。
11. 有先后顺序的玩法，要在代码里守住顺序，不能指望孩子按顺序点。染色体配对时孩子先配 X 和 Y，直接跳到了下一站，星卡也坏了。特殊的那一对要求最后配；自动帮忙的循环每一步先确认还在原来的状态。
12. 成就物（星卡）按固定的排版表画，不要用动画过程中的位置：动画没跑完、或者走了意外的路线，星卡也要是对的。
13. 手机上，动手区的 viewBox 要能缩到操作区域（染色体配对时只显示显微镜视野，相当于放大一倍）；点击判定半径按屏幕像素换算：`max(26, 24 × viewBox 宽 ÷ 画面宽)`。
14. SVG 里的字号用 CSS 类控制，并在 `@media (max-width:520px)` 里放大。注意 CSS 里的 `font-size` 会盖过 SVG 元素上的 `font-size` 属性，写在属性上的大字号其实不生效。
15. 事件的意思要准：探索时的试错（配错一对）不要记成 `answered` 错题，否则会被送进维修舱；同一道题只记一次（猜测用 `predicted`，有标准答案的提问用 `answered`）；「再玩一次」不再发 `complete`。
16. 按住类操作完成时，按钮区会换成「继续」。孩子的手指还按着，一松手就会误点到新按钮，跳过一句话（细胞模块的实现者发现）。新按钮如果是在手指按着时换出来的，先禁用，等这次抬起后再启用；记「手指已抬起」要在 `pointerup` 里立刻做，不能推迟，否则正常点击换出来的按钮也会被禁用。骨架里已经写好。
17. 猜测题的正确答案要轮换位置，选项长度尽量相近；不然孩子很快学会「选最后一个」或「选最长的」（DNA 模块四题的正确答案都在最后）。
18. 选项刚出现的约 400 毫秒内忽略点击，免得双击「继续」时第二下替孩子选了答案；每个错误选项都带误区 id。
19. 计数类的成就不能靠重复点击刷出来：同一样本只计一次，`observed` 也只发一次。星卡写「3 种都找过」，不写可被刷大的数字。
20. 手机滚动：不要在整个 svg 和按钮上设 `touch-action:none`，画面占了大半屏，孩子会滑不动页面。svg 用 `touch-action:pan-y`，拖动开始时再 `preventDefault`；按住类按钮可以用 `none`。
21. 换按钮后把焦点移到新按钮的第一个，键盘用户不用再找。
22. 第 16 条也有键盘版：按住空格「念」到完成时，焦点跳到新出现的「继续」，一松开空格就点了它。按键是在按钮出现之前按下的，就忽略这次按键触发的点击（DNA 模块的修改者发现）。
23. 不变的参照物（合上的书、尺子、底座）放在单独一组、永不重画，给它一个 id。这样「纹丝不动」能用程序断言，不用靠看图；一直闪的提示圈用 CSS 动画（并尊重减少动效），不要每帧重建 SVG。
24. 走查脚本也要守第 18 条：每次点按钮前等够 0.4 秒，不然所有点击都被当成误触，一路卡住。
25. 不要在 `pointerdown` 里用 `innerHTML` 重画手指按着的那个元素：元素被删掉，后面的 `touchstart` 就到不了 svg，拦不住滚动，拖动变成了滚页面。在 svg 最上面放一层永远不重画的透明矩形接收触摸（细胞模块的修改者发现；只用 CDP 触摸测不出来，要按真实触摸事件测）。
26. 领航员的话里不要写颜色（「深色的小圆」）：深色模式下颜色会反过来。
27. 焦点移到 svg 以后，鼠标用户也会看到焦点框；用 `:focus-visible`，只在键盘操作时显示。
28. 窄屏的判断不止 520 px：521～600 px 宽的屏幕仍用 800 宽的排版，字会偏小。需要时按 `svg.clientWidth` 算缩放系数再决定排版。
29. 数字和单位：`1207 万个`、`13 公里`，「万」和量词之间不加空格。
30. 用 `references/starter.html` 起步，不要从零写：卡片、领航员气泡、「我有个问题」、Host 契约、手绘线、按住按钮、tick 和 `fin()` 都在里面。
31. `Host.ready()` 必须先于任何 `state`、`event`：不要把第一站的入口函数（`enter1()` 之类）写在 `Host.ready()` 前面。掰巧克力对比里 Opus 和 Kimi 都犯了这个错。
32. 选择题的正确选项不要总排在同一个位置。孩子很快会发现「答案全是 A」（「生命的说明书」三个挑战就是这样）。题目顺序可以靠 `shuffle` 打乱，选项不会自动打乱，要写的时候就分散开。
33. 第一屏要看得出手放哪。「生命的说明书」把陶土红给了线，把手只是一个黑色小点；掰巧克力的把手是浅粉配灰边，孩子一进动手都在找地方点（Luka 2026-11-14 发现）。强调色只说「看这里」，能用手动的地方另装一个统一的「可抓」记号（圆钮、小圆钮、托、按住按钮，颜色 `--grip`），两者不借颜色；两种颜色明暗接近，所以记号要靠形状认（防滑纹、箭头、墨线外圈），灰度截图检查。提问时不画记号，动手时出现，做完撤掉；没人碰 1.5 秒后提醒第一个。完整规格在 `docs/constellations/zero-to-one/g1.md` A.4「圆钮规格」。按住按钮也不用强调色。

## 检查

- 用 `references/walk.py` 改出这个模块的走查脚本：平板 820×1180 浅色、手机 390×844 深色、电脑 1280×900 浅色加 reduced-motion，每站截图，收集 console 错误。截图逐张打开看。
- 拼一张缩略图总览（每张缩到 410 宽、4 列），一眼看完整个流程。
- 走查脚本写错也会让人误判：判断状态要看当前这道题（`.ask` 的最后一个），不要看整页。
- 试玩页（`preview/build.py`）能直接跑模块：用沙箱 iframe 和 activity/1.1 契约，试玩记录里会有猜测、回答和孩子的问题。
