# Curio AI 中转服务 · 部署手册

这份手册写给任何一个想给孩子打开「AI 答疑」的家庭。不用会写代码：每一步写了打开哪个网址、点哪里、粘贴什么、应该看到什么。照着做完，你会在**自己的**腾讯云账号里有一个只属于你家的中转服务，用你自己的 DeepSeek 余额。

> 腾讯云的控制台偶尔改版。如果按钮的名字和这里写的不一样，找名字差不多的那个；手册里写了「（如果控制台改版，找名字类似『…』的按钮）」的地方，就是写手册的人也拿不准的地方。

## 开始之前，先知道两件事

- **孩子的问题会发送给 DeepSeek。**维护者 2026-11-09 核对过：《DeepSeek 开放平台服务协议》第 4 节规定输入和输出的权利归使用者，没有写把 API 的输入输出用于训练模型；DeepSeek 的网页和 App 对话另有条款，可能在去标识化后用于训练，和这里无关。DeepSeek 的数据在中国境内处理和存储。条款会变，部署前请自己打开 DeepSeek 官网底部的『开放平台服务协议』和『隐私政策』再看一眼。不管条款怎么写，都不要让孩子在问题里写名字、学校、住址、电话；领航员看到这些也会提醒。
- **公开网页由项目维护者托管**，它能读到你在设置里填的家庭口令和孩子的问答（口令要交给网页，网页才能带着它去请求中转）。介意的话，可以把网页放到你自己的静态托管上，见后面「把网页放到自己的地方」一节。公开网页的每个版本都能对应到仓库里的一个提交。

## 它是什么、要花什么钱

```
孩子的平板 ──(家庭口令)──> 你的中转服务（腾讯云云函数） ──(DeepSeek 密钥)──> DeepSeek
                                   │
                                   └─ 记用量、记口令错了几次（腾讯云对象存储 COS）
```

- DeepSeek 的密钥只放在中转服务里，平板上、网页里都没有。
- 花钱的地方有三处：
  1. **DeepSeek**：按问答的长度收费，一次问答大约不到一分钱。你先充一小笔（建议 50 元），用完它自己就停。这是最硬的一道闸。
  2. **腾讯云云函数**：前三个月有免费额度，之后每月有一笔小额基础费用（写手册时约合 1.86 美元），当月完全没有调用就不收。以你部署时页面上的价格为准。
  3. **腾讯云 COS**：只存几个很小的文件，费用几乎为零。
- 中转服务自己还有两道闸：**每天最多问几次**（默认 30 次）、**每月最多花多少**（默认 20 元，按 DeepSeek 用量估算）。

## 要准备的东西

- 一台电脑（Windows 或 Mac 都行），装了新版的 Chrome 或 Edge。
- 一部能收短信的手机（注册、实名用）。
- 两个要下载的文件（第 4 步、第 7 步会说怎么下）：口令小网页 `passphrase.html`、代码包 `curio-relay.zip`。
- 一个记事本（纸的或电脑上的），用来记下面几样东西：**DeepSeek 密钥、家庭口令、桶名、地域、中转服务地址**。记完放好，不要发给别人。

## 第 1 步：注册腾讯云并实名

1. 打开 `https://cloud.tencent.com`，点右上角「注册」（已经有账号就点「登录」）。
2. 按提示用手机号或微信注册。
3. 登录后，按页面提示完成**实名认证**（个人认证就行）。没实名的账号建不了云函数。

**应该看到**：右上角显示你的账号，进「账号中心」能看到「已实名」。

## 第 2 步：给 DeepSeek 充值

1. 打开 `https://platform.deepseek.com`，用手机号注册并登录。
2. 左边点「充值」（如果控制台改版，找名字类似『账户余额』『Top up』的按钮）。
3. **建议第一次只充 50 元。** 这是硬上限：钱用完，DeepSeek 自己就停，不会欠费。

**应该看到**：左边「用量信息」或首页上显示余额 50 元。

## 第 3 步：建 DeepSeek 密钥

1. 还在 `https://platform.deepseek.com`，左边点「API keys」。
2. 点「创建 API key」，名字写 `curio-relay`，点「创建」。
3. 页面会显示一长串以 `sk-` 开头的字。**马上点「复制」，记到记事本里**，标上「DeepSeek 密钥」。这串字只显示这一次，关掉就再也看不到了（丢了就删掉它，重新建一个）。

**应该看到**：API keys 列表里多了一行 `curio-relay`。

> 这串密钥谁拿到都能花你的钱。它只填进第 8 步的云函数设置里，不要发进聊天、不要填进 Curio 网页。

## 第 4 步：生成家庭口令的两行设置

1. 先想一句**家庭口令**：四个随便挑的词，用拼音或英文字母写，中间空一格，格式像 `<词一> <词二> <词三> <词四>`，自己挑四个词。不要用生日、名字、电话。**不能有汉字**：浏览器发请求时，请求头里放不了汉字。记到记事本里，标上「家庭口令」。
2. 在电脑的浏览器里打开 `https://deepnorth2077.github.io/Curio/relay/passphrase.html`，在页面空白处点右键 →「另存为」（Mac 上也可以按 ⌘S），存到桌面。然后**双击桌面上的 `passphrase.html`**，它会在浏览器里打开（建议用 Chrome 或 Edge；新版 Safari、Firefox 也可以）。
   - 为什么要先存下来再打开：存下来的这一份不联网，你输入的口令只在你自己的电脑上算，不经过任何网站。
   - 网页打不开（`github.io` 在国内时好时坏）：换个网络再试，或者用第 7 步「备选」里下载的仓库文件，`relay` → `tools` 里就有 `passphrase.html`。
3. 在「家庭口令」那一栏输入你的口令，点「生成两行设置」。
4. 页面下面出现两行：
   ```
   CURIO_SALT=（一串 32 位的字母数字）
   CURIO_PASSPHRASE_HASH=（一串 64 位的字母数字）
   ```
   各点一下右边的「复制」，分别粘到记事本里。

**应该看到**：两行，第一行以 `CURIO_SALT=` 开头，第二行以 `CURIO_PASSPHRASE_HASH=` 开头。

> 每点一次「生成」，第一行都会变，第二行也跟着变，这是正常的。两行要用同一次生成的，不要混。口令本身不用填到云上，云上只放这两行。

## 第 5 步：建一个 COS 桶，开启版本控制

COS 是腾讯云的「网盘」，中转服务在里面记用量和口令错了几次。

1. 打开 `https://console.cloud.tencent.com/cos`。第一次用会提示开通，点「立即开通」。
2. 左边点「存储桶列表」，点「创建存储桶」。
3. 填：
   - **所属地域**：选离你近的，例如「广州」。**记下括号里的英文代号**，例如 `ap-guangzhou`，记到记事本，标上「地域」。第 8 步建函数时选**同一个地域**。
   - **名称**：例如 `curio`。腾讯云会在后面自动加上一串数字（你的 APPID），变成 `curio-1250000000` 这样。**记下完整的名字**（带数字），标上「桶名」。
   - **访问权限**：选「私有读写」。
   - 其他保持默认，一路点「下一步」，最后点「创建」。
4. 打开刚建好的桶，左边点「容错容灾管理」→「版本控制」，点「编辑」，打开，点「保存」（如果控制台改版，找名字类似『版本控制』『多版本』的开关）。这样文件被改坏或误删，还能找回旧版本。

**应该看到**：存储桶列表里有你的桶，私有读写；版本控制显示「已开启」。

## 第 6 步：建一个能读写这个桶的运行角色

云函数要靠「运行角色」才能读写 COS。不建、不绑，中转服务会一直报存储错误。

1. 打开 `https://console.cloud.tencent.com/cam/role`（访问管理 → 角色），点「新建角色」。
2. 「角色载体」选「腾讯云产品服务」（如果控制台改版，找名字类似『服务角色』的选项）。
3. 产品里找到并选中「云函数（SCF）」，点「下一步」。
4. 「配置角色策略」：在搜索框输入 `QcloudCOSDataFullControl`，勾上它（它的意思是「能读写 COS 里的文件」），点「下一步」。
   - 如果搜不到这个名字，搜 `QcloudCOSFullAccess` 也可以（权限更大一些）。
   - 如果你的腾讯云账号里还有别的重要的桶，想让中转服务只能碰这一个桶，可以请懂的人帮你建一条只管这个桶的自定义策略。不懂的话用上面这条就行。
5. 「角色名称」写 `curio-relay-role`，点「完成」。

**应该看到**：角色列表里有 `curio-relay-role`，载体是云函数。

## 第 7 步：下载代码包（zip）

1. 在电脑的浏览器里打开 `https://deepnorth2077.github.io/Curio/relay/curio-relay.zip`，浏览器会直接下载一个 `curio-relay.zip`。**不要解压，也不要重新压缩**，第 8 步原样上传它。
2. 这个包是 Curio 发布网页时自动在 Linux 上打的，里面第一层是这四样：
   - `scf_bootstrap`（启动文件，没有后缀名，已经带着「可执行」的权限）
   - `package.json`
   - `src` 文件夹（`handler.js`、`navigator.js`）
   - `adapters` 文件夹（`tencent.js`）

**应该看到**：下载文件夹里有 `curio-relay.zip`，几十 KB 大小。

**备选：自己打包**（只在上面的地址打不开时用）

1. 打开 `https://github.com/deepnorth2077/curio`，点绿色的「Code」按钮 →「Download ZIP」，下载后解压，进 `relay` 文件夹。
2. 选中 `scf_bootstrap`、`package.json`、`src`、`adapters` 这四样（不是外面的 `relay` 文件夹），右键压缩：Mac 选「压缩 4 项」；Windows 选「压缩为 ZIP 文件」（或「发送到」→「压缩(zipped)文件夹」）。改名为 `curio-relay.zip`。
3. **在 Windows 上重新压缩，会丢掉 `scf_bootstrap` 的「可执行」权限**，函数会起不来。这时按「常见问题」第 7 条最后一点补救。Mac 自带的压缩一般会保留这个权限。

## 第 8 步：新建 Web 函数，填环境变量

1. 打开 `https://console.cloud.tencent.com/scf`，左边点「函数服务」。第一次用会提示授权，点「同意授权」。
2. 上面选**和第 5 步同一个地域**，点「新建」。
3. 选「从头开始」（如果控制台改版，找名字类似『自定义创建』的选项）。
4. 基础配置：
   - **函数类型**：选「Web 函数」。
   - **函数名称**：写 `curio-relay`。
   - **运行环境**：选 `Nodejs 20`（没有 20 就选 `Nodejs 18`；**不能低于 18**）。
5. 函数代码：
   - **提交方法**：选「本地上传 zip 包」，点「上传」，选第 7 步下载的 `curio-relay.zip`。
   - 如果下面有「启动命令」的设置，不用管：zip 里已经带了启动文件 `scf_bootstrap`，有它的时候控制台的设置不起作用。
6. 展开「高级配置」，找到「环境变量」，一行一行添加（左边填名字，右边填值）。下面前 7 行必须加：

   | 名字 | 值 |
   | --- | --- |
   | `DEEPSEEK_API_KEY` | 第 3 步的 DeepSeek 密钥（`sk-` 开头那串） |
   | `DEEPSEEK_MODEL` | `deepseek-flash`（写这份手册时 DeepSeek「模型和价格」页上 Flash 档的名字；旧名 `deepseek-v4-flash` 也还能用）。部署时请到那一页核对（见下面的说明） |
   | `CURIO_BUCKET` | 第 5 步的桶名（带数字的完整名字，例如 `curio-1250000000`） |
   | `CURIO_REGION` | 第 5 步的地域代号（例如 `ap-guangzhou`） |
   | `CURIO_SALT` | 第 4 步第一行**等号右边**的部分 |
   | `CURIO_PASSPHRASE_HASH` | 第 4 步第二行**等号右边**的部分 |
   | `CURIO_PRICE_FEN_PER_M` | `200,4,800`（写手册时的价格，见下面的说明） |

   下面 3 行可以不加。**不想改默认值，就整行都不要加**（控制台不允许值空着，所以不是「加了名字、值留空」）：

   | 名字 | 值 | 不加这一行时 |
   | --- | --- | --- |
   | `CURIO_DAILY_CALLS` | 每天最多问几次，正整数 | 30 |
   | `CURIO_MONTHLY_FEN` | 每月最多花多少**分**，正整数 | 2000（20 元） |
   | `CURIO_ALLOWED_ORIGINS` | 只有你把网页放到了自己的地方才加（见后面那一节） | `https://deepnorth2077.github.io`（公开网页） |

   已经加了 `CURIO_ALLOWED_ORIGINS` 这一行、删不掉的话，值填 `https://deepnorth2077.github.io`（末尾不要斜杠，不要带 `/Curio`），效果和不加一样。

   粘贴时注意：第 4 步的两行，名字栏填 `CURIO_SALT`，值栏只填等号**右边**那串；值的前后不要多出空格。

7. 点「完成」。第 9 步的几项设置等函数建好以后再改。

**应该看到**：函数列表里有 `curio-relay`，状态是「正常」或「部署完成」。

### 关于模型名

`DEEPSEEK_MODEL` **选 Flash 这一档，不选 Pro**。

写这份手册时（2026 年 11 月），DeepSeek「模型和价格」页（`https://api-docs.deepseek.com/zh-cn/quick_start/pricing/`）列的模型是 `deepseek-flash` 和 `deepseek-v4-pro`，所以这里填 `deepseek-flash`。那一页还注明旧名 `deepseek-v4-flash` 仍可调用、按 Flash 的价格计费，以前填了旧名的不用急着改。现在 DeepSeek 的「思考」是同一个模型上的开关，中转服务每次请求都会把它关掉；你要做的只是选 Flash 这一档，不要选 Pro。部署时请打开这一页，用 Flash 那一档当时的名字。

### 关于单价

`CURIO_PRICE_FEN_PER_M` 是三个整数，单位是「分 / 百万 token」，按顺序是：未命中缓存的输入、命中缓存的输入、输出。

写这份手册时，上面那一页的 Flash 价格分两档：北京时间工作日 9:00–12:00、14:00–18:00 是**高峰**，其余时间是空闲，空闲价是高峰价的一半。**这里用高峰价**（元 / 百万 token）：缓存命中输入 0.04、缓存未命中输入 2、输出 8。换成分：未命中 200、命中 4、输出 800，所以填 `200,4,800`。中转服务一律按高峰价估，空闲时段问的那些会估高一倍，所以估的花费只会偏高、不会偏低，每月上限只会提前到，不会超。

**请部署时打开那一页核对**，价格变了就照新价格换成分再填（1 元 = 100 分，只能写整数，有小数就往上取整）。

## 第 9 步：绑定运行角色、超时 20 秒、并发 10

打开 `https://console.cloud.tencent.com/scf` →「函数服务」→ 点 `curio-relay` →「函数管理」→「函数配置」，点右上角「编辑」：

1. **运行角色**：打开「启用」，在下拉框里选第 6 步的 `curio-relay-role`（如果控制台改版，找名字类似『执行角色』的选项）。**不绑就一直报存储错误。**
2. **执行超时时间**：改成 `20` 秒。默认只有几秒，DeepSeek 想得久一点就会被掐断，页面一直报「DeepSeek 这次没有回答」。
3. 点「保存」。
4. **公网访问**：同一页往下找「网络配置」，「公网访问」要是**开着**的（默认就是开着；如果控制台改版，找名字类似『访问外网』『公网出口』的开关）。中转服务要从函数里去访问 DeepSeek 和 COS，关掉它，每次都会报「DeepSeek 这次没有回答」或存储出错。改了就再点「保存」。
5. **并发上限**：在函数详情页找「并发管理」或「并发配额」，把这个函数的最大并发设成 `10`（如果控制台改版，找名字类似『最大独占配额』『预留并发』的设置）。这样就算有人知道了地址、一直刷，同一时刻最多也只跑 10 个，云函数的费用涨不上去。

**应该看到**：函数配置里，运行角色是 `curio-relay-role`，执行超时时间是 20 秒，公网访问是开着的；并发设置里是 10。

## 第 10 步：拿到中转服务的地址

1. 在 `curio-relay` 的详情页，找「函数 URL」（如果控制台改版，找名字类似『访问路径』『触发管理』的地方）。
2. 如果还没有，点「创建」：**公网访问**打开，**授权类型选「开放」**（中转服务自己用家庭口令把门，这里不用再加一层）。
3. 复制公网地址，形如 `https://……` 的一长串。**记到记事本，标上「中转服务地址」**。地址后面不能再带 `/release` 之类的路径（带了所有请求都会 404，见常见问题第 8 条）。
4. 检查一下：把地址后面加上 `/v1/ping`，粘到浏览器地址栏打开。

**应该看到**：页面上显示 `{"service":"curio-relay","version":1}`。

- 显示 `{"error":"misconfigured"}`：环境变量有填错的。进函数详情页「日志查询」，最新一条会写是哪一项、回手册第几步。
- 显示别的、或者打不开：看最后的「常见问题」。

## 第 11 步：给云账号设一个预算告警

三道闸管的都是 DeepSeek 的钱。云函数和 COS 自己的调用费，靠第 9 步的并发上限和这里的预算告警。

1. 打开 `https://console.cloud.tencent.com/expense`（费用中心），左边找「预算管理」（如果控制台改版，找名字类似『预算』『费用告警』的菜单）。
2. 点「新建预算」，周期选「月」，金额写 `20` 元（或你觉得合适的数），告警阈值选 80% 和 100%，通知方式选短信和邮件。
3. 保存。

**应该看到**：预算列表里有一条每月 20 元的预算。超过时你会收到短信。

## 第 12 步：填进 Curio，跑连通测试

在**孩子用的那台设备**上做（平板、电脑、手机各做一次更好）：

1. 打开 Curio 网页，进家长的「指挥中心」：
   - 平板和电脑：点左边工具条最下面的小锁图标「家长入口」。
   - 手机：点左上角的三条横线（打开知识索引），在弹出来的那一栏最下面点「家长入口」。
   
   输入家长 PIN（第一次是 `1234`；进去以后，在同一页上面的设置卡片里把 PIN 改掉）。进去后往下翻，找到「AI 答疑」卡片。
2. **中转服务地址**：粘贴第 10 步的地址（只到函数地址为止，后面**不要**加 `/v1`）。
3. **家庭口令**：填第 4 步想的那句口令（是口令本身，不是那两行）。
4. 点「保存」。
5. 点「**连通测试**」。

   **应该看到**：「成功 5/5，平均 … 毫秒」，卡片标题旁边变成「已接通」。几百毫秒以内都正常。

6. 点「**试问一个问题**」。

   **应该看到**：几秒内出现领航员对「天空为什么是蓝色的？」的完整回答，下面一行写着今天第几次、本月花了多少。**回答是空的或说到一半断了**：先检查第 8 步的 `DEEPSEEK_MODEL` 是不是 `deepseek-flash`（Flash 档，不是 Pro）。

7. 点「**用量**」。

   **应该看到**：本月每天问了几次、本月一共花了多少。

做完这三样，AI 答疑就能用了。

> 卡片上的「每天最多问几次」只是在页面上显示用。真正的上限在中转服务的环境变量里（`CURIO_DAILY_CALLS`、`CURIO_MONTHLY_FEN`），见下一节。

## 怎么改上限和单价

1. 打开 `https://console.cloud.tencent.com/scf` →「函数服务」→ `curio-relay` →「函数管理」→「函数配置」→「编辑」。
2. 在「环境变量」里改：
   - 每天最多几次：`CURIO_DAILY_CALLS`
   - 每月最多花多少分：`CURIO_MONTHLY_FEN`（2000 就是 20 元）
   - 单价：`CURIO_PRICE_FEN_PER_M`（三个整数，见第 8 步「关于单价」）
3. 点「保存」。下一次请求就按新的算。

中转服务的花费是按单价**估算**的，和 DeepSeek 实际扣的钱可能有一点出入。真正的硬上限是你在 DeepSeek 充了多少钱。

## 怎么换密钥

- **换 DeepSeek 密钥**（怀疑泄露，或者想定期换）：在 `https://platform.deepseek.com` →「API keys」新建一个，复制；到云函数的环境变量里把 `DEEPSEEK_API_KEY` 改成新的，保存；再回 DeepSeek 把旧的删掉。然后在 Curio 里点一次「试问一个问题」确认能用。
- **换家庭口令**：重做第 4 步，得到新的两行；到云函数的环境变量里改 `CURIO_SALT` 和 `CURIO_PASSPHRASE_HASH`，保存；再到每台设备的 Curio 设置里把口令改成新的。

## 把网页放到自己的地方（可选）

用公开网页时，网页的维护者能读到你填的口令和孩子的问答。介意的话，可以自己托管一份：

1. 按第 7 步「备选」第 1 点下载仓库文件并解压，里面的 `prototype` 文件夹就是网页本身。
2. 把它放到你自己的静态网站托管上（例如腾讯云 COS 的「静态网站」功能，或者别的能放网页的地方）。用 COS 的默认域名打开网页时，可能会被当成文件下载而不是直接显示，这时需要绑定一个你自己的域名（国内的域名要先备案）。这一步需要一点动手能力，可以请懂的人帮忙。
3. 记下你的网页地址，例如 `https://curio.你的域名`。
4. 回到云函数的环境变量，填 `CURIO_ALLOWED_ORIGINS`，值是：
   ```
   https://deepnorth2077.github.io,https://curio.你的域名
   ```
   用英文逗号隔开；只想让自己的网页用，就只填自己的地址。只填到域名为止，后面不要带 `/`。
5. 保存，在你自己的网页上重做第 12 步。

## 常见问题

### 1. 一直提示「锁住了」

口令半小时内错了 10 次，中转服务就会锁住，直到最早那次错误满半小时（**家长自己在指挥中心连续输错口令，也会被锁半小时**）。

**马上解锁**：打开 `https://console.cloud.tencent.com/cos` → 你的桶 →「文件列表」→ 进 `auth` 文件夹 → 在 `failures.json` 那一行点「删除」（或「更多」→「删除」）。删掉立刻解锁。

**被反复锁住**（说明有人知道了你的地址，在故意输错口令）：换一个新地址重新部署。在函数服务里新建一个函数（重做第 8～10 步，名字换一个），再**换一个新的桶**（重做第 5 步，改第 8 步里的桶名），或者删掉旧桶里的 `auth/failures.json`，不然旧的错误记录还在。最后把 Curio 里的地址改成新的，旧的函数删掉。

### 2. 一直提示「口令不对」

- Curio 设置里填的应该是**口令本身**（第 4 步想的那句），不是那两行。
- 口令前后不要有空格；大小写要一样；**不能有汉字**（第 4 步）。
- 云函数里的 `CURIO_SALT`、`CURIO_PASSPHRASE_HASH` 要是**同一次生成**的两行，而且只填了等号右边。拿不准就重做第 4 步，两行都换掉。
- 注意：连续错 10 次会被锁半小时，见第 1 条。

### 3. 用量一直是 0，或者提示「中转服务的设置填错了」，日志里说存储出错

- 查第 9 步：函数有没有绑定运行角色 `curio-relay-role`。
- 查第 6 步：这个角色有没有 `QcloudCOSDataFullControl`（或 `QcloudCOSFullAccess`）这条策略。
- 查第 8 步：`CURIO_BUCKET` 是不是带数字的完整桶名；`CURIO_REGION` 是不是和桶的地域一样的英文代号。
- 进函数详情页「日志查询」，看最新一条写的是什么。

### 4. AI 突然全部报错

- **先看 DeepSeek 余额**：打开 `https://platform.deepseek.com`，余额是不是用完了。用完了页面会提示「请家长给 DeepSeek 充值」，充上就好。
- 提示「这个月的花费到上限了」或「今天的次数用完了」：是中转服务的两道闸，等到时间，或者按「怎么改上限和单价」调高。
- 提示「DeepSeek 这次没有回答」：可能是 DeepSeek 临时出问题，过一会儿再试；一直这样，查第 9 步的执行超时是不是 20 秒，再看 DeepSeek 的状态页。
- 提示「中转服务的设置填错了」：进函数「日志查询」，最新一条会写是哪一项、回手册第几步。

### 5. Curio 网页打不开

Curio 的公开网页放在 `github.io` 上，它在国内时好时坏。

- 过一会儿再试，或者换一个网络（比如手机热点）。
- 网页打开过一次以后会存在设备上，网不好时也能先用存下的那份。
- 长期打不开，可以把网页放到自己的地方，见「把网页放到自己的地方」。

### 6. 怀疑有人在刷我的中转服务

- 看第 9 步的并发上限是不是 10，第 11 步的预算告警是不是开着。
- 进函数详情页「监控信息」，看调用次数是不是突然变多。
- 刷中转服务花不了 DeepSeek 的钱（没有口令过不去），但会产生少量云函数费用。确实被刷，就按第 1 条「被反复锁住」的办法换个地址。

### 7. 连通测试显示「成功 0/5」「连不上」

- 地址有没有复制完整、是不是 `https://` 开头、后面有没有多加东西（只到函数地址为止）。
- 用浏览器直接打开「地址 + `/v1/ping`」（第 10 步第 4 点），能看到 `{"service":"curio-relay","version":1}` 吗？
  - 能看到，但 Curio 里连不上：多半是网页的地址不在允许名单里。用公开网页的不用改；用自己托管网页的，查 `CURIO_ALLOWED_ORIGINS`。
  - 浏览器里打不开：看函数 URL 是不是「公网访问」「开放」；函数状态是不是「正常」。
  - 函数日志里说启动失败，或者浏览器一直等不到回应：多半是 zip 里的 `scf_bootstrap` 丢了「可执行」的权限（用 Windows 压缩时可能发生）。在函数详情页「函数代码」里打开在线编辑器，找到「终端」（如果控制台改版，找名字类似『Terminal』的菜单），粘贴下面这一行回车，再点「部署」：
    ```
    chmod 755 scf_bootstrap
    ```

### 8. 所有请求都是 404（连 `/v1/ping` 都是）

函数的地址可能带了一段路径前缀，例如 `https://……/release/`（用 API 网关触发器时常见）。中转服务只认 `/v1/…` 开头的路径，前面多一段，所有请求都会 404。

- 改用第 10 步的「函数 URL」，它的地址后面不带路径。
- 如果只能用带前缀的地址，在 API 网关里把这个前缀去掉（找名字类似『路径映射』『发布环境』的设置），让 `地址 + /v1/ping` 能直接打到函数上。拿不准就请懂的人帮忙。
