# 「生命的说明书」进正式星图

## 舰长能做什么

正式星图里的细胞、染色体、DNA 各有「动手探索」和「挑战」。第一次进探索，从第一站开始。每当「去下一站」或「看星卡」可点，这一站就算做完。离开、刷新再回来，舰长可以重玩做完的站，也可以继续下一站。单站重玩跳过开头的猜测，玩完回到选站页。拿过星卡后仍可从头玩。完成探索沿用星图的「探索过」，挑战仍按原来的规则点亮。

## 宿主和进度

- 发布包沿用正式星图已有的发布清单。宿主核对模块清单和入口 HTML 的字节数与哈希，用一次运行专属的 `sandbox="allow-scripts"` iframe 加载 HTML。文档最前面设置 CSP，限制资源和连接。模块只接收活动需要的初始化信息。
- 接收消息时核对当前窗口、契约版本、运行阶段、消息种类、清单声明的动词和数据形状。模块不能指定孩子、活动或记录序号。连续的画面更新不会挤掉完成消息。离开时先处理已收到的进度，再结束本次尝试；载入失败、再次导航或失去写锁时停止接收。
- 正式外壳按活动登记站数（`app/exploration.js`）：生命座三个模块各 4 站，「0 和 1 之间」19 个模块各 3 站（#233）。站号超过站数的标记不记；做完全部站才接受完成。数学模块打开时若有做完的站，先让孩子选「重玩第 k 站」或「从头玩」；星卡要用到每一站的结果，所以不从中间接着做。
- 三个模块的四站都使用同一个明确的完成标记：`observed` 的结果为 `{station: 1…4, item: "station-complete"}`。其中途操作（看一次读数、试一次配对）各有自己的消息，都不解锁下一站。
- 宿主依次写已有的 `attempt.started`、每个新站一次 `sim.observed`（`observable: "station.completed"`、`value` 为站号），以及一次结束事件。只完成部分的尝试也保留已完成站。宿主重建当前孩子、活动及版本的进度，在 `init.completed_stations` 给出站号，在 `init.activity_completed` 给出是否拿过星卡。沿用 event/2、已有备份和恢复。
- 这次记录整站和活动的完成情况。逐次猜测和读数的长期映射、信号站里的问答分别留到相应切片。正式探索在初始化时关闭提问入口，避免舰长把问题交给尚未接入的信号站。

## 怎么验收

1. 打开正式星图，依次点细胞、DNA、染色体。每颗星都能进入自己的探索和挑战。
2. 做完探索第一站，回星图，刷新后再进。选第一站直接动手，完成后回到选站页；也能顺序去第二站。另一颗星仍从自己的起点开始。
3. 做完全部四站并领星卡。回星图看到「探索过」，再进能选第四站重玩。
4. 进染色体挑战。问「多少条」时填 23，问「多少对」时填 46，分别得到能帮助换一种数法的线索。其他数字按原有规则反馈。
