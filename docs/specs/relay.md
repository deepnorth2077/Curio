## 问题

孩子想问「为什么」的时候，平台现在只能把问题记下来，等家长回答。接 AI 必须有地方放 DeepSeek 的密钥：放在页面里，孩子的设备上就能翻出来，谁拿到都能花钱。这个地方放在云上（ADR-010），并且**每家一份**：以后别的家庭照同一份手册，在自己的云账号里部署自己的中转、用自己的密钥。

## 方案

云上一个很小的中转服务：页面带着家庭口令请求它，它检查口令和上限，再带着自己保管的密钥去问 DeepSeek，把回答交回页面。花费有三道闸。代码一份，首批部署到腾讯云云函数；处理函数不绑平台，以后加别的平台只多一个薄适配层。部署好以后在孩子的设备上跑连通测试。

## 用户故事

1. 作为家长（包括以后别的家庭），我想要照着手册复制粘贴就能在自己的云账号里部署好中转服务，这样不用会写代码，也不用把密钥交给别人。
2. 作为家长，我想要在孩子的平板上点一下就知道中转服务通不通、快不快，这样部署完就知道能不能用。
3. 作为家长，我想要 AI 一个月最多花多少钱由我定，到了就停，这样不会有意外账单。
4. 作为家长，我想要在指挥中心看到这个月问了几次、花了多少，这样心里有数。
5. 作为家长，我想要别人拿到页面也用不了我的额度，这样密钥和余额是安全的。
6. 作为舰长，我想要问了问题几秒内得到听得懂的回答，不确定的地方领航员会直说，这样我能相信它。
7. 作为维护者，我想要中转服务的规则能在 Node 里不联网测完，并且有手算的验收用例，这样换平台、改上限都有把握。

## 实现上的决定

### 1. 目录

```
relay/
  src/handler.js        handle(request, env, deps) → Response：全部规则都在这里
  src/navigator.js      领航员说明（system prompt）和回答的长度约束
  adapters/tencent.js   腾讯云 Web 函数的入口：把平台的请求转成标准 Request，存储用 COS
  test/                 node:test 测试，含验收用例
  DEPLOY.md             部署手册（给部署的家长，每一步写点哪里、看到什么）
```

- JavaScript ES 模块，不引入依赖，不打包（ADR-008）。平台适配层只做转换，不含规则。首批只有腾讯云的适配层；以后要加 Cloudflare 等平台，只加一个 `adapters/<平台>.js`。
- `deps` 把外部依赖都传进来：`deps.storage`（`get(key) → string | null`、`put(key, string)`）、`deps.upstream(body) → {status, json}`（调用 DeepSeek）、`deps.now() → 毫秒时间戳`。测试时换成内存版本，不联网、不读时钟。`storage.get`、`storage.put`、`upstream` 都可以返回 Promise，`handle` 一律 `await`；DeepSeek 的 15 秒超时由 `upstream` 实现，超时就抛错。

### 2. 配置（平台的环境变量）

| 变量 | 说明 | 默认 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | DeepSeek 密钥。只在这里 | 必填 |
| `DEEPSEEK_MODEL` | 模型名。用 Flash 一档（2026-11 价格页上的名字是 `deepseek-flash`；旧名 `deepseek-v4-flash` 还能调用）。DeepSeek 现在的思考是同一个模型上的开关、默认打开，所以请求里必须带 `thinking: {"type": "disabled"}`（第 4 节第 6 步）：开着思考会把 400 token 的上限花在推理上，回答变空，花费也不同 | 部署手册里写当时的名字 |
| `CURIO_BUCKET`、`CURIO_REGION` | 存用量和失败记录的 COS 桶名和地域 | 必填 |
| `CURIO_PASSPHRASE_HASH` | `sha256(盐 + 家庭口令)` 的十六进制小写 | 必填 |
| `CURIO_SALT` | 盐，随机字符串（由下面的小网页生成，不要自己想） | 必填 |
| `CURIO_ALLOWED_ORIGINS` | 允许跨域的来源，逗号分隔。别的家庭用同一个公开网页时不用改；自己另外托管网页的，填自己的地址 | `https://deepnorth2077.github.io` |
| `CURIO_DAILY_CALLS` | 每天最多几次（本地日期，UTC+8） | 30 |
| `CURIO_MONTHLY_FEN` | 每月最多花多少分（本地月份，UTC+8） | 2000（20 元） |
| `CURIO_PRICE_FEN_PER_M` | 单价，「分 / 百万 token」，三个整数用逗号分开：未命中缓存的输入、命中缓存的输入、输出 | 部署手册里写当时的**高峰**价（有闲时折扣时，按高峰价估的花费只会偏高，上限更保险） |

部署手册附一个本地小网页（单文件，不联网）：家长只输入口令，它自己生成随机盐，直接输出 `CURIO_SALT=…`、`CURIO_PASSPHRASE_HASH=…` 两整行，整行复制粘进平台设置。口令本身不进任何平台。手册建议口令用四个随机的词，不用生日、名字。**口令只能用可打印的 ASCII 字符**（英文字母、拼音、数字、空格和常见符号），首尾不能是空格：浏览器不允许请求头里有汉字，带汉字的口令根本发不出去，小网页和指挥中心都要拦下并说明。

**启动时自检**：`CURIO_PASSPHRASE_HASH` 不是 64 位小写十六进制、盐为空、`CURIO_DAILY_CALLS` 或 `CURIO_MONTHLY_FEN` 填了但不是正整数、桶名或地域为空、`DEEPSEEK_API_KEY` 或 `DEEPSEEK_MODEL` 为空、单价不是三个非负整数（逗号两边的空格忽略）时，除 `OPTIONS` 预检外的每个请求（包括 `GET /v1/ping`，这样连通测试就能暴露配置错）都回 500 `misconfigured`，并在平台日志里写一句人话，指明是哪一项、回手册第几步。

### 3. 接口

全部是 JSON；请求体超过 4 KiB 直接回 413 `too_large`，不解析。

**CORS**（它只管浏览器能不能读到响应，**不是**访问控制，访问控制靠口令）：

- 每个响应（包括错误响应）都带 `Vary: Origin`；没有 `Origin` 头的请求（比如 curl）照常处理，不回 ACAO。
- 请求的 `Origin` 在 `CURIO_ALLOWED_ORIGINS` 里时，回 `Access-Control-Allow-Origin: <那个来源>`；不在名单里就不回这个头，请求照常处理。
- `OPTIONS` 预检（不论路径）回 204，名单里的来源再加 `Access-Control-Allow-Methods: GET, POST, OPTIONS`、`Access-Control-Allow-Headers: authorization, content-type`、`Access-Control-Max-Age: 600`。名单里的来源在所有响应上再加 `Access-Control-Expose-Headers: Retry-After`，不然页面读不到要等多久。页面带 `Authorization` 和 JSON 请求体，一定会先发预检，少了这几个头就调不通。

带口令的响应（`tutor.ask`、`usage`）都加 `Cache-Control: no-store`。没有的路径回 404 `not_found`，路径对、方法不对回 405 `method_not_allowed`。

| 接口 | 口令 | 说明 |
| --- | --- | --- |
| `GET /v1/ping` | 不要 | 回 `{"service": "curio-relay", "version": 1}`。连通测试用。故意不要口令、不受锁定影响：连通测试要能分清「连不上」和「口令不对」 |
| `POST /v1/capabilities/tutor.ask` | 要 | 问一个问题，见下 |
| `GET /v1/usage` | 要 | 回本月用量，见下 |

**口令**放在请求头 `Authorization: Bearer <家庭口令>`，`Bearer` 不分大小写。中转服务算 `sha256(盐 + 口令)`，和 `CURIO_PASSPHRASE_HASH` 做定长比较。

**`tutor.ask` 请求**：

```json
{"question": "为什么我的眼睛像妈妈？", "age_band": "G3-4", "context": {"node_title": "染色体", "activity_title": "把说明书卷好收起来"}}
```

- `question`：去掉首尾空白后 1～200 个字符（按 Unicode 码点数）；`age_band` 是 `G1-2`、`G3-4`、`G5-6`、`G7-9`、`G10-12` 之一；`context` 可选，有就必须是对象（`null` 也不行）；`node_title`、`activity_title` 都可选，有就必须是字符串，各最多 40 个字符。不满足 → 400 `{"error": "bad_request"}`。

**成功的响应**：

```json
{"answer": "……", "usage": {"calls_today": 3, "daily_calls": 30, "fen_month": 1, "monthly_fen": 2000}}
```

`fen_month` 是本月已花的分数，向上取整。

**错误**：

| 状态 | `error` | 什么时候 |
| --- | --- | --- |
| 400 | `bad_request` | 请求格式不对 |
| 401 | `bad_passphrase` | 口令不对（计一次失败） |
| 429 | `locked` | 被锁定中（口令对也一样） |
| 429 | `daily_cap` | 今天的次数用完 |
| 429 | `monthly_cap` | 本月的花费到了上限 |
| 413 | `too_large` | 请求体超过 4 KiB |
| 404 / 405 | `not_found` / `method_not_allowed` | 路径或方法不对 |
| 500 | `misconfigured` | 平台设置填错了（见启动时自检） |
| 502 | `no_balance` | DeepSeek 说余额不足（它回 402 时）。页面提示「请家长给 DeepSeek 充值」 |
| 502 | `upstream` | DeepSeek 别的错误或超时（15 秒） |

429 都带 `Retry-After`（秒）：`locked` 到解锁为止，`daily_cap` 到本地第二天 0 点，`monthly_cap` 到本地下个月 1 日 0 点。页面可以显示「还要等多久」。

页面按 `error` 显示给孩子能懂的话，例如 `daily_cap`：「今天的问题问完啦，明天再来，或者请家长调高额度。」`no_balance`、`misconfigured`、`locked` 对孩子只说「AI 暂时用不了，请家长看看」，具体原因显示在指挥中心。

**`GET /v1/usage`**：

```json
{"month": "2026-11", "calls_by_day": {"2026-11-07": 3}, "fen_month": 1, "daily_calls": 30, "monthly_fen": 2000}
```

### 4. 规则（按顺序判断）

**任何请求的总顺序**：`OPTIONS` 预检（第 3 节，直接回 204）→ 路由（没有的路径 404，方法不对 405）→ 启动时自检（500 `misconfigured`）→ 请求体大小（413）→ 下面各步。404、405、413、500 都不计失败、不计次数。`usage` 请求走下面第 1～3 步（锁定期间同样回 `locked`），不走第 4 步以后。

一个 `tutor.ask` 请求进来：

1. 格式不对 → 400。不计失败、不计次数。
2. **锁定**：存储里记着失败时间，只算距现在**不到 1800 秒**的（更早的丢掉）。这样的有 10 个或更多 → 429 `locked`，锁到窗口里的记录少于 10 个为止，`Retry-After` 按这个时刻算。锁定期间不新增失败记录；记录最多存 10 条，多出的（并发时可能发生）丢最早的。存回去时只存窗口里的记录；「清空」就是存成 `{"times": []}`。
3. **口令**不对（包括没有 `Authorization` 头、格式不是 `Bearer <口令>`）→ 记下这次失败的时间 → 401。口令对 → 清空失败记录。

锁定可以被人拿来把这家锁在门外（中转的地址是公开的，知道地址的人先发 10 个错口令，之后大约每半小时补 1 个，就能一直锁住）。这是**有意接受的取舍**：它不泄露口令、不花 DeepSeek 的钱，只影响能不能用；不锁的话，口令就可以被无限次地猜。应急办法写进部署手册「常见问题」的第一条：到 COS 控制台删掉 `auth/failures.json`，立刻解锁；被反复锁住就换一个新地址重新部署，同时换一个新的桶，或者删掉旧桶里的 `auth/failures.json`，不然旧的失败记录还在。家长自己在指挥中心连续输错口令，也会被锁半小时，手册里写明。
4. **今天的次数**（UTC+8 的本地日期）已经 ≥ `CURIO_DAILY_CALLS` → 429 `daily_cap`。
5. **本月花费**已经 ≥ `CURIO_MONTHLY_FEN` → 429 `monthly_cap`。
6. 调用 DeepSeek：请求体是 `{model, messages, max_tokens: 400, thinking: {"type": "disabled"}, stream: false}`（`messages` 由 `navigator.js` 的 `buildMessages` 生成）。DeepSeek 回 402 → 502 `no_balance`；别的非 2xx、超时、连不上，或者回了 200 但没有 `choices[0].message.content`、内容是空字符串 → 502 `upstream`。都不计次数；如果 DeepSeek 回了用量，花费照记；没有用量就不写存储。
7. 成功：今天的次数加一，按用量加上花费，存回存储，回答交给页面。

`GET /v1/usage` 同样先查锁定和口令（第 2、3 步），通过后回用量，不计次数。

**花费**用整数算，单位是「百万分之一分」：

```
花费 = 未命中缓存的输入 token × 单价1 + 命中缓存的输入 token × 单价2 + 输出 token × 单价3
```

单价的单位是「分 / 百万 token」，所以乘出来正好是百万分之一分。本月累计存成这个单位的整数；比较上限时用 `累计 ≥ 上限分 × 1000000`；给页面看的 `fen_month` 是 `累计 ÷ 1000000` 向上取整。DeepSeek 的用量字段：`prompt_cache_miss_tokens`、`prompt_cache_hit_tokens`、`completion_tokens`；两个都缺的时候，把 `prompt_tokens` 全部算作未命中；只缺一个，缺的那个算 0。

**存储里的两个文件**：`usage/<YYYY-MM>.json`（`{calls_by_day: {日期: 次数}, cost_ufen: 整数}`），`auth/failures.json`（`{times: [毫秒时间戳…]}`）。新的月份就是新文件，旧的保留，家长以后想看历史也能看。

**存储出错**：读存储失败，或者读到的内容不是合法 JSON、格式不对 → 500 `misconfigured`（内容坏了的，日志说是哪个文件、到 COS 控制台删掉它）；日志指向手册里「绑定运行角色」那一步（最常见的原因）。DeepSeek 已经回答、但写用量失败时，回答照样交给页面，日志记一句；这次的次数和花费就漏记了，由预充值兜底。

**并发**：读改写之间不加锁。一个孩子几乎不会同时发两个问题；万一同时发，可能丢一次计数更新，计数偏低，上限略松，最多多花一两次的钱，由 DeepSeek 预充值兜底（ADR-010 第 5 条）。

**日期**：从毫秒时间戳算本地日期和月份，一律写成「UTC 字段加 8 小时再进位」的纯函数，**不用**运行环境的本地时区方法（云函数的时区不一定是 UTC，换平台更说不准）。

### 5. 领航员说明

`navigator.js` 里的 system prompt 要点（措辞由 Claude 在派发时写定，照 `life-manual.md` 的领航员说话方式）：

- 你是好奇号的领航员，对面是舰长（一个 `age_band` 年龄段的孩子），叫他「舰长」。
- 用这个年龄能懂的话，句子短，一次回答不超过 150 个字；能举身边的例子就举。
- 不确定、或者科学上还没有定论的，直接说「这个我也不确定」或「科学家还在研究」，不编造。
- 不出现「学习」二字。不问孩子的名字、住址、学校。
- 涉及危险、身体不舒服、和别人起冲突、或者不适合孩子的问题：不给具体做法，请舰长去找家长。
- 舰长的问题里出现名字、住址、学校、电话这类内容时，回答里不复述、不展开，温和地提醒一句「这些事不用告诉电脑哦」，再回答问题本身。
- 最后可以抛一个「你可以自己试试看」的小问题。

`context` 有的时候，告诉领航员舰长正在看哪颗星、哪个活动。

### 6. 指挥中心（原型里先做，正式外壳随第二段）

设置里的「AI 答疑」卡片（已有地址、口令、每日上限三栏）加上：

- **连通测试**：对 `GET /v1/ping` 连续请求 5 次，每次最多等 5 秒，显示「成功 X/5，平均 Y 毫秒」。全部失败时提示「连不上：检查地址，再看部署手册的『常见问题』」。
- **试问一个问题**：用固定的问题「天空为什么是蓝色的？」调用 `tutor.ask`，显示回答和用量。
- **用量**：调用 `GET /v1/usage`，显示本月每天的次数和本月花费（存储只记本月总花费，不分天）。
- 页面上的「每天最多问几次」只是显示用，真正的上限在中转服务的设置里，卡片上要写明这一点。

### 7. 部署手册（`relay/DEPLOY.md`）

**代码包**：每次 `main` 上的 `relay/` 变化，发布网页的工作流在 Linux 上把 `scf_bootstrap`、`package.json`、`src/`、`adapters/` 打成 `curio-relay.zip`，和口令小网页一起放在 `https://deepnorth2077.github.io/Curio/relay/`。手册第一选择是下载这个 zip 直接上传（可执行位已经在里面）；自己打包是备选，并写明 Windows 上重新压缩会丢掉可执行位。

写给任何一个家庭（不只是 Luka），每一步写明：打开哪个网址、点哪里、粘贴什么、应该看到什么。包括：给 DeepSeek 充值（建议第一次只充 50 元）、在 DeepSeek 后台建密钥、用小网页生成两行设置、建 COS 桶并开启版本保留、部署函数、填环境变量（包括桶名和地域）、**给函数绑定能读写这个桶的运行角色**（不绑就一直报存储错误）、**把函数的执行超时设成 20 秒**（默认只有几秒，不改就一直 502）、**把函数并发上限设成 10、给云账号设一个预算告警**（防止公开的地址被刷云函数和 COS 的调用费；三道闸只管 DeepSeek 那一个钱包）、拿到地址、填进好奇号的设置、跑连通测试和「试问一个问题」（几秒内收到完整回答；回答为空或被截断，先检查模型是不是非思考档）。

手册开头写两句透明说明：
- **孩子的问题会发送给 DeepSeek**，按它当时的数据处理条款处理。部署前 Claude 核对一次当时的条款，把结论写进那一版手册。
- **公开网页由项目维护者托管**，它能读到家长在设置里填的口令和孩子的问答（口令要交给网页，网页才能带着它去请求中转）。介意的家庭可以把网页放到自己的静态托管上（正式选项，手册里有一节），再把自己的地址加进 `CURIO_ALLOWED_ORIGINS`。公开网页的每个版本都能对应到仓库里的一个提交。

手册最后写「怎么改上限和单价」（单价和 DeepSeek 实际计价有出入时，以预充值为硬上限）、「怎么换密钥」「常见问题」。常见问题至少有：一直锁着（删 `auth/failures.json`）、一直提示口令不对、用量一直是 0 或存储报错（检查运行角色）、AI 突然全部报错（先看 DeepSeek 余额）、网页打不开（`github.io` 在国内时好时坏，见下）、怀疑被刷（看并发上限和预算告警）。手册里不出现任何一个家庭的地址、口令或密钥。

## 测试接缝

| 接缝 | 能发现 | 发现不了 |
| --- | --- | --- |
| `handle(request, env, deps)` + 内存存储 + 假的 DeepSeek + 固定时钟 | 口令、锁定、两种上限、花费算法、日期和月份按 UTC+8 切换、错误码、CORS、请求校验、不存原文 | 平台适配层、真实网络 |

| 让一个没参与制作的人（或子 agent）只看 `DEPLOY.md` 走一遍 | 手册有没有漏步骤、写得是不是不懂代码也能照做 | 平台控制台以后改版 |

**验收用例**（Claude 手算，派发时写成 `relay/test/cases.json`，这里列关键几条）：

| 情况 | 期望 |
| --- | --- |
| 单价 `200,20,800`；一次用量：未命中 1000、命中 500、输出 300 | 花费 = 1000×200 + 500×20 + 300×800 = 450000 百万分之一分；`fen_month` = 1 |
| 上限 2000 分，累计 1999999999 | 还能再问一次（< 2000000000）；问完累计 ≥ 上限，下一次 429 `monthly_cap` |
| 每天 30 次，今天已经 30 次 | 429 `daily_cap`；本地时间第二天 00:00（UTC 16:00）起恢复 |
| UTC 2026-11-30T15:59:59.999Z 和 2026-11-30T16:00:00.000Z 各问一次 | 分别记进 `usage/2026-11.json` 和 `usage/2026-12.json` |
| 口令连错 10 次，第 1 次在 t0、第 10 次在 t（都在 1800 秒内） | 第 10 次本身回 401；t 之后、t0 + 1800 秒之前，口令对也回 429 `locked`，`Retry-After` = t0 + 1800 − 现在（向上取整到秒）；之后恢复 |
| 30 分钟前有 9 次失败，现在又错 1 次 | 只有 1 次算数，回 401，不锁 |
| 口令连错 9 次，第 10 次对 | 200，失败记录清空 |
| DeepSeek 回 500，没有用量 | 502，次数和花费都不变 |
| `question` 是 201 个汉字 | 400；不计失败、不计次数 |
| `Origin` 不在允许名单 | 正常处理，但响应里没有 `Access-Control-Allow-Origin` |
| 名单里的 `Origin` 发 `OPTIONS` 预检 | 204，带 ACAO、`Allow-Methods`、`Allow-Headers: authorization, content-type`、`Vary: Origin` |
| 名单外的 `Origin` 发预检 | 204，没有 ACAO |
| DeepSeek 回 402 | 502 `no_balance`，次数和花费不变 |
| 请求体 5000 字节 | 413 `too_large`，不计失败、不计次数 |

| 第 1 次失败在 t0，到第 10 次都在 1800 秒内；现在正好是 t0 + 1800 秒 | t0 那条不再算（「不到 1800 秒」），只剩 9 条，口令对 → 200 |
| 没有 `Authorization` 头 | 401，记一次失败 |

| 成功的 `tutor.ask` 和 `usage` 响应 | 都带 `Cache-Control: no-store` |
| 锁定期间带对口令请求 `usage` | 429 `locked` |
| 任何请求之后 | 存储里找不到问题和回答的原文 |

## 不做什么

- 舰长在领航员对话里提问、存私人文字和事件、标记回答不对：第二段。
- 同步和备份：CURIO-008，方向见 ADR-010 第 7 条。
- 拍照识题、举一反三：以后各自定规格，沿用 `/v1/capabilities/<能力名>`。
- 两个模型交叉核对：Luka 2026-11-06 决定先不做。
- 几个家庭共用一个中转、在中转里区分家庭：不做（ADR-010 第 2 条）。
- Cloudflare 等别的平台的适配层：等有需要再加。
- 流式输出：回答很短，一次给完。

## 其他

- 第二段的事件怎么记（AI 的回答用哪个动词、`actor` 是谁）要先修订事件规格：现在 `question.answered` 的 `actor` 只能是孩子或家长。打算加 `system`（`sys:relay`），在第二段的规格里改，走外部审阅。
