# 规格：画风的唯一出处，零件库和颜色下发（CURIO-010）

- 状态：提议
- 依据：ADR-011（提议）、ADR-003、ADR-005、ADR-008、`docs/activity-contract.md`、内容规格 3.8
- 实现任务：ADR-011 接受后另开，分三个竖切片（见「怎么分步」）

## 问题

- 作为维护者：同一套颜色、手绘线、页面骨架抄在五处以上，名字还不统一。改一次画风要逐个文件改，修一个骨架缺陷要逐个模块改。
- 作为实现者：每个新模块要先抄 300 行骨架，再在里面改。抄错、改坏都发生过。
- 作为舰长：宿主换了明暗模式，模块里的淡彩色块不跟着变；试玩页根本不下发颜色。

## 方案

- 颜色和明暗模式由宿主在 `init` 里发全，键名写进契约。
- 骨架和手绘线放进 `kit/<版本号>/`，由工具写进模块里标好的两段，CI 逐字节核对。
- 外壳的基础颜色也从同一处同步。

做完以后：在一个地方改一个颜色，外壳、试玩页、所有模块一起变；新模块只写自己的模型、场景和台词。

## 用户故事

1. 作为舰长，我想要模块和外面的页面颜色一致，这样不会觉得突然换了一个地方。
2. 作为家长，我想要已经发布的模块不被悄悄改掉，这样孩子昨天玩过的东西今天还是那样。
3. 作为维护者，我想要改颜色只改一处，这样十年里换画风不用逐个改模块。
4. 作为维护者，我想要 CI 告诉我谁动了库的代码，这样不用靠人逐字比对。
5. 作为实现者，我想要从一个只有标记和示例站的薄骨架起步，这样不会改坏不该改的地方。

## 实现上的决定

### 1. 契约 activity/1.2（相对 1.1 只增不改）

`init` 的 payload：

| 字段 | 1.1 | 1.2 |
| --- | --- | --- |
| `age_band`、`lang`、`phase`、`mastery` | 有 | 不变 |
| `palette` | 有，键名没规定 | 键名固定为下面 20 个，宿主要发全，值是 CSS 颜色字符串 |
| `scheme` | 没有 | `"light"` 或 `"dark"` |

`palette` 的 20 个键（就是 CSS 变量去掉 `--`）：

`bg`、`pane`、`hover`、`rule`、`ink`、`text`、`muted`、`accent`、`accent-soft`、`sage`、`sage-bg`、`sky`、`apricot`、`paper`、`dad`、`mom`、`good`、`good-soft`、`bad`、`bad-soft`

模块的规则：

- 对 `palette` 里每个认识的键，设置同名的 CSS 变量；不认识的键忽略；缺的键用库里的默认值。
- 值只接受 `#` 开头的 3、4、6、8 位十六进制颜色。别的写法一律忽略。原因：值会进 `style`，不能让它带进别的东西。
- 收到 `scheme` 后，在根元素上设置 `color-scheme`，并且不再根据系统的明暗设置换默认值。没收到 `scheme`（单独打开时）才看系统设置。

宿主的规则：

- 消息里的 `contract` 用模块 manifest 里写的值。宿主同时认 `activity/1.1` 和 `activity/1.2`。
- 对两种模块都发 20 个键的 `palette` 和 `scheme`。
- manifest 里 `contract` 是别的值的模块，不加载（内容规格 3.8 已有这条）。

`schemas/activity.schema.json`：`contract` 从 `const` 改成 `enum: ["activity/1.1", "activity/1.2"]`；增加可选的 `kit`（正整数）；`kit` 只允许和 `activity/1.2` 一起出现。

### 2. 库的目录和内容

```
kit/
  1/
    kit.css     颜色变量的默认值（浅色、深色）、字体、三种线（k、k1、kf）、卡片、气泡、按钮
    kit.js      Host、sketchLib、P、T、clamp、smooth、lerp、head、hint、readout、say、actions、ask、next、「我有个问题」
    README.md   这一版有什么、和上一版的差别
```

第 1 版的内容，就是 `references/starter.html` 现在第 2、3、4 节和 `<style>` 里与具体模块无关的部分，加三处改动：

- `Host.on("init", …)` 按上面「模块的规则」处理 `palette` 和 `scheme`。
- `Host.ready()` 由库在脚本末尾的 `Kit.start(enter)` 里先发，再调用模块的入口。模块不再自己排这个顺序（`lessons.md` 第 31 条）。
- 深色的默认值单独放在一个类里（`.kit-dark`），由 `scheme` 或系统设置决定加不加，不再写死在 `@media (prefers-color-scheme:dark)` 里。

### 3. 标记和工具

模块和外壳文件里，库的位置用注释标出，样式一段、脚本一段：

```
/* curio-kit:1 begin */
…工具写入的内容，不要手改…
/* curio-kit:1 end */
```

外壳文件只需要颜色变量，用另一种标记，内容取自 `kit.css` 里的变量部分：

```
/* curio-tokens:1 begin */ … /* curio-tokens:1 end */
```

`tools/kit.py`：

- `python tools/kit.py sync <文件>…`：把标记之间的内容换成 `kit/<标记里的版本号>/` 的内容。文件里没有标记就报错，不猜位置。
- `python tools/kit.py check`：检查仓库里所有带标记的文件。任何一段和原件不是逐字节相同，就列出文件和段，退出码非零。
- 换行一律 LF；标记行本身不算内容。

`tools/ci_checks.py` 增加三条：

- manifest 写了 `kit: N` 的模块，`index.html` 里必须有 `curio-kit:N` 的两段，并且通过 `check`。
- 带标记但版本号在 `kit/` 里不存在的，报错。
- `kit/<N>/` 下的文件，如果已有合入 `main` 的模块或外壳在用这一版，就不能改（比较 `origin/main` 上的同名文件）。新版本用新目录。

### 4. 外壳

- `prototype/index.html`、`app/index.html`、`preview/template.html` 的基础颜色变量换成 `curio-tokens` 段。外壳原来的名字作为别名写在段的后面：`--c-sci: var(--sage)`、`--c-math: var(--apricot)`、`--c-sky: var(--sky)`、`--wash: var(--paper)`。
- 外壳多出来的变量（地铁线的颜色、阴影等）留在各自的文件里，不进库。
- 原型的 `palette()` 改成按 20 个键取值；试玩页不再发空表；两者都发 `scheme`。
- `references/starter.html` 变成薄骨架：两段标记、`MODEL`、两个示例站、`Kit.start(enter1)`。

## 怎么分步

每一步是一个能单独演示的行为。

| 步 | 做完以后能看到什么 | 改到哪里 |
| --- | --- | --- |
| 1 | 把染色体模块换成用库以后，三种环境下的截图和消息序列都和原来一样 | `kit/1/`、`tools/kit.py` 和测试、CI、schema、契约文档、染色体模块（改版）、薄骨架 |
| 2 | 在 `kit/1/kit.css` 里改一个颜色再同步，原型、演示页、试玩页的底色一起变；原型切到深色，模块里的淡彩色块也跟着变 | 三个外壳文件、`palette()`、试玩页的 `init` |
| 3 | 用薄骨架做一个新模块（或改版一个旧模块），模块自己的代码在 400 行以内 | 下一个知识点的模块 |

第 1 步里，库的第 1 版必须和现在的骨架行为相同（除了上面写明的三处改动）。

## 测试接缝

| 接缝 | 能发现 | 发现不了 |
| --- | --- | --- |
| `tools/kit.py check` 的退出码和输出 | 有人手改了库的代码；标记缺了或版本号不存在 | 库本身写得对不对 |
| 模块发给宿主的消息序列（`ready`、`state`、`event`、`complete`） | 迁移以后行为变了；`ready` 不是第一条 | 画面的变化 |
| 三种环境下每一站的截图，迁移前后逐像素比较 | 迁移以后画面变了 | 截图没覆盖到的中间状态 |
| 宿主发 `init` 以后，模块根元素上的 CSS 变量值 | 颜色没有跟着宿主变；不合格的值被写了进去 | 颜色好不好看 |
| `schemas/activity.schema.json` 对 manifest 的校验 | `kit` 写错、`kit` 和 1.1 一起出现 | — |

期望值从哪来：

- 消息序列和截图的期望值，是迁移**之前**的模块在同一个走查脚本下的输出，先存下来再迁移。
- CSS 变量的期望值，是测试里写死的颜色字符串。
- `check` 的正反例：一份没动过的（通过）、一份改了一个字符的（不通过）、一份标记缺一半的（不通过）、一份版本号不存在的（不通过）。

验收用例（实现时逐条写成测试）：

1. 宿主发 `palette: {accent: "#123456", sage: "#abcdef"}`、`scheme: "dark"`：模块的 `--accent` 是 `#123456`，`--sage` 是 `#abcdef`，`color-scheme` 是 `dark`，其余变量是深色的默认值。
2. 宿主发 `palette: {accent: "red; background:url(x)"}`：`--accent` 保持默认值。
3. 宿主发 `palette: {accentSoft: "#123456"}`：没有任何变量改变。
4. 模块单独打开、系统是深色：用深色的默认值。
5. 库里 `kit.js` 的第一条发给宿主的消息是 `ready`，早于任何 `state`。
6. 染色体模块迁移前后：三种环境（平板 820×1180 浅色、手机 390×844 深色、电脑 1280×900 浅色加减少动效）下，消息序列相同；每站截图不同的像素不超过 0.5%。
7. 四个 1.1 模块一个字节不改，在发 20 键 `palette` 的宿主里从头玩到星卡，没有契约警告。

## 不做什么

- 不改任何颜色的值，不改线宽和字号。这份规格只管「从哪来」，不管「长什么样」。
- 不把线宽、字号、动效放进契约（ADR-011「放弃的方案」）。
- 不迁移全部已发布的模块：第 1 步只迁移染色体，其余等各自改版时再迁。
- 不处理字体文件。字体随项目自带是 ADR-005 第 8 条、ADR-008 第 5 条已经定的事，另开任务。
- 不做正式外壳里的活动宿主（状态机、配额、CSP）。那是竖切片 5（#28）；这份规格只规定宿主在 `init` 里发什么。
- 不给库加把手、小牌子、拨盘等新零件。等第二个模块要用时出第 2 版。

## 其他

- 新词要加进 `GLOSSARY.md`：**零件库**（`kit/`，模块共用的骨架和手绘线，按版本管理）。避免：组件库、框架。
- 风险：第 1 步的「行为相同」如果做不到逐像素，要先查清原因再放宽 0.5% 这个数，不能直接改数。
