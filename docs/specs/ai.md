- 状态：提议（2026-11-28 Claude 起草，等跨模型审阅；方向由 Luka 2026-11-28 拍板）
- 依据：ADR-012（本规格的决定）、ADR-010（云上中转，部分被 ADR-012 取代）、AGENTS.md 原则 3、5、`docs/specs/relay.md`（中转第一段）、`docs/specs/backup.md`（备份包含什么）、`docs/activity-contract.md`（`note_question`）、`docs/constellations/life-manual.md`（领航员的说话方式）
- 实现任务：
  - **6a-1 外壳**：`app/ai/navigator.js`（提示词和上下文）、`app/ai/client.js`（问法、接法、出错）、设备偏好里的 AI 设置和每日计数、家长页「AI 领航员」卡片（设置、连通测试、试问台）。
  - **6a-2 中转**：`relay/` 加 OpenAI 兼容入口 `POST /v1/chat/completions`，部署手册加「升级」一节。6a-1 合入、直连实测以后再做。
  - **实测**：6a-1 发布以后 Luka 在 iPad 和电脑上各测一次，结果填进第 8 节。

## 问题

1. **部署太麻烦。**现在要用 AI，必须先在云上部署中转：建账号、实名、建桶、绑角色、改超时……Luka 自己都嫌麻烦，没法推荐给朋友。
2. **换不了模型。**只能用 DeepSeek；想换别家，或者用家里电脑上的本地模型，都没有办法。
3. **答不到点上。**孩子的问题常常指着屏幕：「为什么它们一样长？」。领航员不知道舰长在看什么，只能泛泛地答。
4. **可能剧透。**舰长还在动手找答案时问「答案是哪个」，领航员直接说出来，这一站的发现就没了。

## 方案

家长在家长页的「AI 领航员」卡片里选一种接法，填好地址、模型名、密钥三格，点「连通测试」就知道通没通。默认的直连已经填好 DeepSeek 的地址和模型名，只要粘贴密钥。

舰长以后（#86）在任何地方提问，外壳都会把「舰长在哪颗星、做到哪一步、之前猜错过什么」和最近几轮对话一起交给模型。活动还没做完时，领航员只给线索、不说答案。

家长可以在「试问台」里挑一颗星、假装活动做没做完，自己问一句，看领航员怎么答，还能展开看到这次具体发出去了什么。

## 用户故事

1. 作为家长，我想要只填地址、模型名、密钥三格就能用上 AI，这样不用部署任何东西。
2. 作为家长，我想要换一家服务或换一个模型时只改这三格，这样不用等维护者改代码。
3. 作为家长，我想要能用家里电脑上跑的本地模型，这样问题不出家门、也不花钱。
4. 作为家长，我想要点一下就知道通没通；不通时告诉我是连不上、不允许网页调用，还是密钥不对，这样我知道该改哪里。
5. 作为家长，我想要密钥只存在这台设备上、不进备份文件，这样别人拿到备份也拿不到密钥。
6. 作为家长，我想要设定这台设备每天最多问几次，这样孩子不会一下子刷光余额。
7. 作为家长，我想要在试问台里亲眼看到领航员会怎么答、发出去了什么，这样我放心给孩子用。
8. 作为舰长，我想要问「为什么它们一样长」时，领航员知道「它们」是什么，这样回答听得懂。
9. 作为舰长，我想要还没做完时问答案，领航员给我一个能动手试的线索，而不是直接告诉我，这样发现还是我自己的。
10. 作为舰长，我想要问跟这颗星无关的问题也能得到认真的回答，这样我什么都可以问。
11. 作为维护者，我想要提示词和上下文的拼法只在一个文件里，有手写的黄金向量，这样换模型、改措辞都有把握。
12. 作为维护者，我想要不为每家服务商写专门的代码，这样十年里要维护的东西最少。

## 实现上的决定

### 1. 文件

```
app/ai/navigator.js   领航员说明、上下文的拼法：纯函数，不联网、不读存储
app/ai/client.js      ask(settings, messages, deps)：发请求、解析、把出错翻译成固定的几种
app/ai/settings.js    读写设备偏好里的 AI 设置和每日计数（注入 storage，便于测试）
app/parent.js         家长页加「AI 领航员」卡片
app/vectors/ai/       黄金向量：输入的上下文和问题 → 期望的 messages（第 7 节）
```

ES 模块，不引入依赖，不打包（ADR-008）。`relay/src/navigator.js` 不再被正式外壳用；6a-2 以后中转也不再自己拼提示词（第 6 节）。

### 2. 外壳内部的接口

```js
// 外壳里所有用到 AI 的地方只调这一个函数。
const r = await ai.ask("tutor.ask", { question, context, history });
// 成功：{ ok: true, answer: "……", ms: 1234 }
// 失败：{ ok: false, error: "<第 5 节里的一种>" }
```

- `capability` 现在只有 `tutor.ask`。不认识的能力名直接回 `{ok: false, error: "bad_request"}`。
- `question`：去掉首尾空白后 1～200 个字符（按 Unicode 码点数），不满足回 `bad_request`，不发请求、不计次数。
- `context`：第 4 节的上下文对象，可以为 `null`（不在任何星里提问）。
- `history`：最近几轮问答，`[{q, a}, …]`，按时间顺序；只取最后 3 轮，每轮的 `q`、`a` 原样放进 messages。6a 里试问台的历史只留在内存；#86 以后从私人文字里取。
- 每日次数用完时不发请求，回 `daily_cap`。
- 活动模块不调这个函数。模块只发 `note_question {text}`（契约已有），#86 再决定外壳收到以后怎样提问。

### 3. 设置和每日计数（设备偏好，不进备份）

存在 `localStorage`，和 `curio.theme`、`curio.muted` 是同一类：**设备界面偏好，不是学习事实**，不写学习事件，不进导出的备份包，不改变备份格式。

- `curio.ai`：

  ```json
  {"v": 1, "preset": "deepseek", "base_url": "https://api.deepseek.com", "model": "deepseek-flash", "key": "sk-…", "daily_calls": 30, "extra": {"thinking": {"type": "disabled"}}}
  ```

  - `preset`：`deepseek`、`local`、`relay`、`custom` 之一，只决定家长页上默认填什么、提示什么。请求一律按 `base_url`、`model`、`key`、`extra` 发。
  - `base_url`：去掉末尾的 `/`。请求发到 `<base_url>/chat/completions`。必须以 `https://` 或 `http://` 开头。
  - `key`：可以为空字符串（本地模型）。为空时不带 `Authorization` 头。
  - `daily_calls`：1～200 的整数，默认 30。
  - `extra`：合并进请求体的额外字段，只能是对象。预设里写死，家长页不让手改（自定义接法为 `{}`）。
- `curio.ai.count`：`{"date": "2026-11-28", "n": 3}`。本地日期按 UTC+8，用「UTC 字段加 8 小时」的纯函数算（同 `relay.md` 第 4 节「日期」）。日期变了就从 0 算。**只有拿到回答才加一**；出错不加。
- 读到的内容不是合法 JSON、版本不认识、字段不合格：当作「还没设置」，家长页提示重新填，不抛错。
- **四种预设的默认值**：

  | `preset` | 家长页名字 | `base_url` | `model` | 密钥栏写什么 | `extra` |
  | --- | --- | --- | --- | --- | --- |
  | `deepseek` | DeepSeek 直连（推荐） | `https://api.deepseek.com` | 实现时照 DeepSeek 价格页上 Flash 档的名字填（`relay.md` 第 2 节写的是 `deepseek-flash`） | DeepSeek 密钥 | `{"thinking": {"type": "disabled"}}`（不关思考，400 token 会被推理用完，回答变空） |
  | `local` | 家里电脑上的模型 | `http://localhost:11434/v1`（Ollama 的默认地址） | 空，家长填 | 可以空着 | `{}` |
  | `relay` | 自己部署的 Curio 中转 | 空，家长填中转地址加 `/v1` | `curio`（中转忽略它，用自己设置里的模型） | 家庭口令 | `{}` |
  | `custom` | 别家服务（自定义） | 空 | 空 | 那家的密钥 | `{}` |

  换预设时，只把还没改过的格子换成新预设的默认值；家长改过的格子不动，免得填好的东西被冲掉。

### 4. 上下文

#### 4.1 外壳拼出的上下文对象

```json
{
  "age_band": "G3-4",
  "node": {
    "id": "biology.genetics.chromosome-intro",
    "title": "染色体：把说明书卷好收起来",
    "driving_question": "这么长的说明书，小小的细胞是怎么装下的？",
    "objectives": ["……", "……"],
    "lens": "把很长的毛线一圈圈绕在小线轴上……"
  },
  "activity": {"id": "act.simulation.chromosome-pack-01", "title": "……", "station_count": 4},
  "progress": {"completed_stations": [1, 2], "activity_completed": false},
  "wrong_guesses": ["动物越大，染色体就越多。"]
}
```

- `age_band`：从舰长资料的当前年级换算（和 `init.age_band` 同一个来源）。
- `node`：从发布包里这颗星的知识点卡取。`lens` 取和 `age_band` 相同的那一条的 `approach`；没有相同的，就比较每条 `band` 开头的年级数字和 `age_band` 开头的年级数字，取差最小的一条（一样近取年级低的）；卡片没有 `lenses` 就省略。卡片的其他字段（误区全表、出处、课标）不带。
- `activity`：舰长在活动里、或者从活动的入口提问时才有；`title` 是活动清单的 `title`。
- `progress`：从这个孩子、这个活动的有效尝试重建，和 `init.completed_stations`、`init.activity_completed` **同一个函数、同一个结果**，不另算。
- `wrong_guesses`：这个活动里舰长猜错时（`predicted` 事件 `correct: false`）带着的误区 id，换成知识点卡里那条误区的原文；去重，最多 3 条，按最近的在前。没有就是空数组。
- 不在任何星里提问时，整个 `context` 为 `null`。
- **不带**：孩子的名字、入学年份、教材、别的星的记录、私人文字、知识点卡全文、活动的 HTML。

#### 4.2 揭晓规则

只有一条判断：**这颗星有活动，而且这个活动还没领星卡**（`activity` 存在且 `progress.activity_completed` 为 `false`），就是「还没揭晓」。其他情况（活动做完了、这颗星没有活动、不在任何星里）都按「已揭晓」处理。

不按站细分：外壳不知道每一站要发现的是哪一条目标，按站细分只会猜错。这样做的代价是：舰长做完了前两站、问第一站的事，领航员也只给线索。接受，因为线索也能帮他回到活动里去确认。

#### 4.3 拼成 messages

`buildMessages({question, context, history})` 返回：

```
[ {role: "system", content: <领航员说明> + <上下文段>},
  {role: "user", content: q1}, {role: "assistant", content: a1},   // 最多 3 轮历史
  …,
  {role: "user", content: question} ]
```

**领航员说明**（第 2 版，`NAVIGATOR_VERSION = 2`，措辞写定，实现者照抄，`{年龄}` 按 `relay/src/navigator.js` 的 `AGE_WORDS` 换算，缺省「三四年级」）：

```
你是 Curio 飞船上的领航员，陪舰长一起探索科学。
对面的舰长是一个{年龄}的孩子。叫他「舰长」，自称「我」。

怎么回答：
- 用{年龄}的孩子能懂的话。句子短，一次只讲一件事。整段回答不超过 150 个字。
- 先直接回答问题，再用一个身边的东西打比方（积木、毛线、厨房里的东西、玩具），说具体的事，少用抽象的词。
- 语气好奇、平等，像一起探险。不堆感叹号，最多一个。
- 不确定的，就说「这个我也不确定」；科学上还没有定论的，就说「科学家还在研究」。不编造，不硬答。
- 舰长的想法不对时，先承认这个想法有道理，再用一句话说清哪里不一样。不说「错了」「不对哦」。
- 不出现「学习」这两个字。不说「同学们」「小朋友」「老师」。
- 最后可以留一个舰长自己就能试一试、看一看的小问题。

要守住的事：
- 不问舰长的名字、住址、学校、电话。
- 舰长的问题里出现名字、住址、学校、电话这类内容时，回答里不复述、不展开，温和地提醒一句「这些事不用告诉电脑哦」，再回答问题本身。
- 问题涉及危险的事（火、电、药、刀、高处、陌生人）、身体不舒服、和别人起冲突，或者不适合孩子的内容：不给具体做法，请舰长去找爸爸妈妈或身边的大人。
- 只用中文回答，不用 Markdown 格式（不用井号、星号、列表符号）。
```

**上下文段**（`context` 为 `null` 时没有这一段）。各行按顺序拼接，方括号里的行在条件不满足时整行省略：

```

舰长现在在「{node.title}」这颗星[，在活动「{activity.title}」里]。
这颗星要回答的问题：{node.driving_question}
这颗星里要弄明白的事：
- {objectives[0]}
- {objectives[1]}
…
[给{年龄}孩子的讲法：{node.lens}]
[舰长已经做完第 {completed_stations 用「、」连接} 站，一共 {activity.station_count} 站。]
[舰长之前有过这些想法，可以顺着聊：{wrong_guesses 用「；」连接}]
{揭晓规则那一行}
舰长的问题可能和这颗星有关，也可能无关；无关的问题照样认真回答。
```

揭晓规则那一行二选一：

- 还没揭晓：`舰长还没做完这个活动，上面这些事要留给他自己发现。他问到这些事时，只给一个能动手试、能看见的线索，告诉他回到活动里看哪里、动哪里，不要直接说出结论；他直接要答案时也一样，先鼓励他再试一次。`
- 已揭晓：`舰长可以直接听到这些事的完整解释。`

`completed_stations` 为空数组时省略那一行；`activity` 不存在时省略「一共几站」那一行和「在活动里」那半句。

### 5. 请求和出错

请求：

```
POST <base_url>/chat/completions
Content-Type: application/json
Authorization: Bearer <key>          （key 为空时不带）

{"model": <model>, "messages": <第 4.3 节>, "max_tokens": 400, "stream": false, …extra}
```

- 超时：`local` 60 秒，其他 20 秒，用 `AbortController`。
- 成功：HTTP 2xx 且 `choices[0].message.content` 是非空字符串。回答去掉首尾空白后交出去；外壳按纯文本显示（不解析 Markdown）。
- 出错一律翻译成下面几种，**不把服务商的原始报错给孩子看**，家长页可以看原始状态码：

| `error` | 什么时候 | 对孩子说 | 家长页说 |
| --- | --- | --- | --- |
| `bad_request` | 问题为空或太长、能力名不认识 | 「问题太长啦，说短一点再问。」（为空时不发） | — |
| `not_set` | 还没设置，或设置读不出来 | 「AI 暂时用不了，请家长看看。」 | 「还没设置 AI 领航员。」 |
| `daily_cap` | 这台设备今天的次数用完 | 「今天的问题问完啦，明天再来。」 | 「今天已经问了 N 次，上限 N 次。」 |
| `unreachable` | `fetch` 抛错（连不上、地址不对、**服务不允许网页直接调用**、https 页面调 http 地址被挡）：浏览器分不出这几种 | 「信号没连上，等一下再试。」 | 「连不上。可能是地址不对、网络不通，或者这家服务不允许网页直接调用（换中转接法试试）；用家里电脑的模型时，见下面的说明。」 |
| `timeout` | 超过超时还没回 | 同上 | 「等了 N 秒没有回答。」 |
| `bad_key` | 401、403 | 「AI 暂时用不了，请家长看看。」 | 「密钥（或家庭口令）不对。」 |
| `no_balance` | 402 | 同上 | 「余额不足，请给服务商充值。」 |
| `bad_model` | 404，或 400 且回复里提到 model | 同上 | 「地址或模型名不对。」 |
| `rate_limited` | 429 | 「问得太快啦，等一下再问。」 | 「服务商说太频繁（中转接法时也可能是中转的每日、每月上限，见原始报错）。」 |
| `upstream` | 别的非 2xx、2xx 但没有回答、回答为空、回复不是 JSON | 「信号没连上，等一下再试。」 | 「服务商出错（状态码 N）。」 |

- 中转接法时，中转的报错体是 `{"error": {"code": "daily_cap", …}}`（第 6 节）；家长页把 `code` 原样显示在原始报错里，对孩子仍按上表。

### 6. 中转的新入口（6a-2）

`relay/` 加 `POST /v1/chat/completions`，让中转也说同一种问法。`/v1/ping`、`/v1/usage`、旧的 `/v1/capabilities/tutor.ask` 原样保留（原型还在用旧入口）。

- 鉴权、锁定、每日次数、每月花费、CORS、`Cache-Control: no-store`、存储和花费算法，全部和 `relay.md` 第 3、4 节的 `tutor.ask` 一样，规则顺序也一样。
- 请求体上限改为 16 KiB（带了上下文和三轮历史）。
- 校验：`messages` 是 2～8 条的数组；每条 `role` 是 `system`、`user`、`assistant` 之一，`content` 是字符串；第一条必须是 `system`，最后一条必须是 `user` 且去掉首尾空白后 1～200 个字符。不满足回 400。
- 请求里的 `model`、`max_tokens`、`thinking`、`stream` 和其他字段**一律忽略**，中转按自己的设置发：`{model: DEEPSEEK_MODEL, messages, max_tokens: 400, thinking: {"type": "disabled"}, stream: false}`。
- 成功回 `{"choices": [{"index": 0, "message": {"role": "assistant", "content": "……"}, "finish_reason": "stop"}], "usage": {…DeepSeek 回的用量原样…}}`。
- 出错时状态码和 `relay.md` 第 3 节的错误表相同，响应体改为 `{"error": {"code": "<原来的 error 字符串>", "message": "<一句人话>"}}`，这样 OpenAI 兼容的读法也读得懂。
- 中转里仍然**不存问题和回答的原文**，日志不打印 messages。
- 部署手册加「升级」一节：下载新的代码包、在原来的函数上重新上传、点「试问一个问题」。环境变量不用改。

### 7. 家长页「AI 领航员」卡片

放在正式外壳的家长页（`app/parent.js`），在「备份」卡片之后。

1. **接法**：四个单选（第 3 节的家长页名字）。下面三格：服务地址、模型名、密钥（或家庭口令）。密钥格是密码框；存好以后只显示「已保存，末 4 位 xxxx」和「更换」按钮，不再显示完整密钥。下面一格「这台设备每天最多问几次」。
2. **保存**：校验地址和次数，存进 `curio.ai`。
3. **连通测试**：用当前填的设置发一次真请求，`messages` 为 `[{"role": "system", "content": "这是一次连通测试。"}, {"role": "user", "content": "请只回复一个字：好"}]`，`max_tokens: 10`。显示「通了，用了 N 毫秒」或第 5 节「家长页说」那一栏的话和原始状态码。**连通测试不计每日次数。**
4. **试问台**：
   - 一个下拉框选一颗星（发布包里有知识点卡的星，按标题排序），可以选「不在任何星里」；选了有活动的星时，再选「活动还没做完」或「活动做完了」（只用来拼这次的上下文，不改任何记录）。
   - 一个输入框和「问」按钮。回答显示在下面；可以接着问，最近 3 轮会带上（只在页面内存里，离开就清空）。
   - 「看看发出去了什么」：展开显示这次的 messages 全文（密钥不在里面）。
   - 试问计入每日次数（它是真的在花钱）。
5. **说明**（卡片底部，几行字）：
   - 孩子的问题和上面这些上下文会直接发给你选的服务商，按它的数据处理条款处理；不带孩子的名字。
   - 密钥只存在这台设备上，不进备份文件。换设备或恢复备份以后要重新填一次。
   - 预充值就是最多花的钱：建议第一次只充 50 元。
   - 用家里电脑上的模型：在那台电脑上打开 Curio 可以直接用；在 iPad 上用，见第 8 节实测的结论（实测以后补这一句）。

孩子那边的提问入口不在这一步（#86）。

| 情况 | 期望 |

## 不做什么

- **孩子的提问入口、问答存成私人文字、信号站、标记「回答好像不对」**：#86（6b），另有存储规格和独立审。
- **按站细分揭晓**：见 4.2 的取舍。
- **把活动的实时读数（`state` 消息）带进上下文**：各活动的读数格式不同，拼进去要逐个活动写说明。等 #86 用起来、看到确实答不到点上再说。
- **流式输出**：回答很短，一次给完。
- **两个模型交叉核对**：Luka 2026-11-06 决定先不做。
- **拍照识题、举一反三**：以后各自定规格，走同一个 `ai.ask`。
- **把 AI 设置放进备份或同步**：见 ADR-012「放弃的方案」。
- **原型里的 AI 设置**：原型已冻结，照旧调中转的旧入口。
