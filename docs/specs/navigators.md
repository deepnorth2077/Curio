# 规格：可以选的领航员，点亮星座认识新的一位（CURIO-012，#111）

- 状态：提议（Luka 2026-11-11 已回答四个问题，等外部审阅）
- 依据：ADR-003（发布不可变）、ADR-004（状态由投影产生）、ADR-005（活动宿主）、ADR-006（可恢复性）、ADR-011（提议，零件库和契约 1.2）；内容规格 3.6、6；事件规格 6.4；竖切片 1 规格第 4 节（掌握度）；竖切片 5a 规格（提议）；`GLOSSARY.md`
- 实现任务：规格接受后另开，分三步（见「怎么分步」）

## 问题

- 作为舰长：领航员是每一屏都陪着我的角色，可它只有一个样子，不是我选的。
- 作为家长：孩子点亮一个星座以后，除了星星变了样，没有一件「属于他」的东西留下来。打卡工具里「收集」这件事在孩子身上是管用的（架构文档 D12）。
- 作为维护者：领航员的样子现在写死在每个模块和每个外壳文件里，换不了。

## 方案

领航员可以有好几位。

- 一开始有两位：「小灯」和「小环」（#105 的设计稿）。第一次打开时，舰长挑一位陪他。
- 以后每点亮一个指定的星座，就**认识**一位新的领航员。认识了就一直认识，不会再失去。
- 舰长随时可以在认识的几位里换。换了以后，外壳里和动手探索里出现的都是他选的那一位。
- 每一位说话的方式都一样，不一样的只有样子、名字和一句见面的话。

## 用户故事

1. 作为舰长，我想要第一次进来时自己挑一位领航员，这样它是我选的伙伴。
2. 作为舰长，我想要点亮一个星座以后认识一位新的领航员，这样我做到的事有东西留下来。
3. 作为舰长，我想要看到还没认识的领航员的影子，和「点亮哪几颗星就能认识它」，这样我知道往哪飞。
4. 作为舰长，我想要随时换回原来那一位，这样新的不喜欢也没关系。
5. 作为舰长，我想要进了动手探索以后，旁边说话的还是我选的那一位，这样不会觉得换了人。
6. 作为家长，我想要认识了就不会再失去，这样孩子不会因为后来做错一道题而丢掉伙伴。
7. 作为家长，我想要这件事不花补给点、不限时间、不催，这样它是惊喜，不是压力。
8. 作为维护者，我想要加一位新的领航员只是加一份内容，不改代码，这样十年里可以一位一位地加。
9. 作为维护者，我想要每一位都是原创的，这样公开的仓库和页面里没有别人的角色。

## 实现上的决定

### 1. 领航员是内容

每一位领航员是内容仓库里的一个目录，随发布包走：

```
content/navigators/nav.<短名>/
  navigator.yaml
  curious.svg  waiting.svg  surprised.svg  clap.svg  think.svg  wrong.svg
```

`navigator.yaml`（schema `navigator/1`）：

```yaml
id: nav.lamp                 # 永不复用、永不改动
schema: navigator/1
version: 1
title: 小灯                   # 给舰长看的名字，最多 6 个字
intro: 我头顶有一盏小灯，想到什么它就亮。   # 见面时说的一句话，最多 40 个字
unlock:
  start: true                # 一开始就认识
review: pending              # pending | claude-reviewed | approved
author: {model: <实际模型>, prompt_ref: <设计说明的路径>}
```

不是一开始就认识的那些，`unlock` 写成：

```yaml
unlock:
  lit: [biology.cell.cell-intro, biology.genetics.dna-intro, biology.genetics.chromosome-intro]
  from: 生命的说明书          # 给舰长看的星座名
```

规则：

- 六个表情都要有，文件名固定：`curious`（好奇，平时）、`waiting`（等你）、`surprised`（惊讶）、`clap`（鼓掌）、`think`（想一想）、`wrong`（算错了）。
- 每个 SVG：`viewBox="0 0 48 48"`；只用内容规格 3.6 白名单里的元素和属性；能画出东西的元素（`path`、`circle`、`ellipse`、`rect`、`line`、`polyline`、`polygon`）不超过 14 个；不带 `text`。
- 颜色不写死在文件里，用 `class`：`k`（粗墨线）、`k1`（细墨线）、`f-ink`、`f-pane`、`f-sky`、`f-sage`、`f-apricot`、`f-paper`、`f-accent`（填色）。只允许这九个类。浅色、深色由平台的样式决定，一套线稿两种模式都能用。
- `f-accent` 每个表情里最多用在一个元素上（强调色只给一处）。
- `unlock` 二选一：`start: true`，或者 `lit` 加 `from`。`lit` 是 1 到 12 个知识点 id，都必须是 `status: published` 的知识点。
- **已发布的领航员，`id` 和 `unlock` 永远不能改。**要换条件，就出一位新的领航员。改画法、改名字、改见面的话是普通的改版（`version` 加一）。
- 发布包只收录 `review: approved` 的领航员；发布包里至少要有一位 `start: true` 的。

发布清单多一个键 `navigators`，写法和 `activities` 相同（每个文件的路径、字节数、SHA-256）。收录了领航员的发布包，`engine_min` 至少是 2：旧的外壳不认识这个键，会显示「需要更新」，不会读错。

### 2. 认识了谁：从已有的掌握度算，不加新事件

```js
knownNavigators(mastery, navigators)
// mastery：projectMastery(events) 的输出
// navigators：发布包里的领航员定义
// → 已认识的领航员 id 列表，按 id 的码点排序
```

一位领航员算「已认识」，当且仅当：

- 它是 `start: true`；或者
- 它的 `lit` 里**每一个**知识点，在 `mastery.nodes` 里都有，并且 `best` 不是 `null`，并且 `best.correct × 5 ≥ best.answered × 4`。

说明：

- 用的是 `best`（做得最好的那一次挑战），不是 `state`。`best` 只会变好，不会变差，所以认识了就不会再失去。星星后来因为有了没修好的错题而不算「已点亮」，不影响已经认识的领航员。
- 这是一个纯函数：同样的事件、同样的发布包，算出同样的结果。不写新的事件，不改事件格式，不改内核。
- 它放在 `engine/js/navigators.js`，不碰 DOM、存储和时间。

### 3. 选了谁：记在孩子的档案里

- 档案里加两个字段：`navigator_id`（现在选的是谁）和 `navigators_seen`（已经和舰长打过招呼的 id 列表）。它们存在外壳的本地存储里（和设备信息放在一起），不是事件。
- 显示用的领航员这样定：`navigator_id` 在「已认识」里就用它；否则用「已认识」里 `start: true` 的第一位（按 id 排序）。这种情况不改写档案里存的值。
- 第一次打开（`navigator_id` 还没有值）时，先请舰长挑，挑完才进星图。
- 换领航员不影响任何记录。

### 4. 舰长看到的

**第一次打开。**两位一开始就认识的领航员并排站着，各说自己的那句 `intro`。下面一行字：「舰长，选一位陪你出发吧。以后随时可以换。」点一位，它换成鼓掌的表情，按钮写「出发」。

**认识新的一位。**做完挑战回到星图时，如果「已认识」里出现了不在 `navigators_seen` 里的 id，就出一张卡片（一次只出一位，其余的下次回星图再出）：

- 先是影子，然后露出它惊讶的表情，再换成好奇的表情；
- 卡片上写：「你点亮了『生命的说明书』。有一位新的领航员想认识你。」下面是它的名字和 `intro`；
- 两个按钮：「让它陪我」「先不换」。点哪个都把这个 id 记进 `navigators_seen`，卡片不再出现；
- 尊重 `prefers-reduced-motion`：不做影子变实的过程，直接显示。

**领航员舱。**星图页上现在这位领航员的头像可以点，进去是一排卡片，一位一张：

- 已认识的：好奇的表情、名字；现在陪着的那位有一个记号；点一下就换。
- 还没认识的：只有影子（六个表情里 `curious` 的轮廓，填成灰色），不写名字。下面写：「点亮『生命的说明书』的三颗星，就能认识它。」每颗已经做到的星打一个勾。
- 不显示一共有几位还没做出来的，不显示百分比。

入口不占导航：它是星图页上的一个头像，不是第六个入口（AGENTS.md：只有一套导航）。

**外壳里。**凡是领航员说话的地方（竖切片 5a 窄栏下面的那几句话、以后的讲解对话和信号站），头像都用现在选的这一位，表情按场合：提问时「等你」，答对「鼓掌」，答错「想一想」，揭晓「惊讶」，其余「好奇」。

### 5. 动手探索里也是它（依赖 ADR-011）

- 宿主在 `init` 里多发一个 `navigator`：`{id, faces: {curious, waiting, surprised, clap, think, wrong}}`，每个值是那张 SVG 去掉最外层 `<svg>` 以后的内容。它来自核对过哈希的发布包。
- 零件库的第 2 版负责用它：`say(text, tone, mood)` 的第三个参数是表情。不传时按 `tone` 定：没有 `tone` 是 `curious`，`good` 是 `clap`，`bad` 是 `think`；`ask()` 等舰长回答时是 `waiting`。模块想要「惊讶」或「算错了」，自己传。
- 没收到 `navigator`（单独打开，或者宿主是旧的）时，用库里自带的那一位。
- 用旧骨架的 activity/1.1 模块显示的还是它们自带的那张脸。它们改版换到零件库第 2 版以后，才会跟着舰长的选择变。

### 6. 每一位都是原创的

- 不以任何现成的角色为原型：动画、游戏、绘本、吉祥物、品牌形象都不行。换画风、换颜色、换姿势也不行。
- 审查里有一条固定的检查：请一个没看过设计说明的审查者只看图，问「它让你想起哪个现成的角色吗？」说得出来，就打回。
- 想让领航员贴近孩子的喜好，从两样东西出发：孩子自己画的一张画；或者孩子用自己的话说的「我喜欢它什么」（勇敢、安静、跑得快这类性格和本事，不是长相）。设计说明里只写这些，不写任何现成角色的名字。
- 设计方法照 #105：每位六个表情，42 px 时分得清，强调色只给一处。

### 7. 说话的方式只有一种

- 所有领航员共用星座约定里的「领航员怎么说话」。模块里的台词、AI 中转的领航员说明（`relay/src/navigator.js`）都不按领航员分。
- 原因：台词是按模块一句一句写好、审过的；按领航员各写一套，内容量翻几倍，也没法保证每一套都讲对。
- 每位领航员自己的话只有一句 `intro`，只在见面和领航员舱里出现。

## 演示步骤（Luka 亲手验收，iPad）

N1：

1. 清掉演示页的数据再打开。先看到两位领航员并排，各说一句话。
2. 点「小环」，它鼓掌；点「出发」，进星图。星图页上有小环的头像。
3. 点头像，进领航员舱。小环有「陪着你」的记号；还有一个灰色的影子，下面写着要点亮哪三颗星。
4. 点「小灯」。回星图，头像变成小灯。刷新页面，还是小灯。

N2：

5. 把细胞、DNA、染色体三颗星的挑战都做到点亮。做完第三个回到星图，出现卡片，里面是新的领航员。
6. 点「先不换」。头像还是小灯。再回一次星图，卡片不再出现。
7. 进领航员舱，第三位不再是影子，可以点它换上。

N3：

8. 选第三位，进染色体的动手探索。旁边说话的是第三位；猜错时它是「想一想」的表情，做完一站时它鼓掌。

## 不做什么

- 不用补给点换领航员，不抽，不限时，不做「连续几天」的条件。认识新领航员只有一条路：点亮指定的几颗星。
- 不按领航员写不同的台词，不给 AI 中转换人设（见第 7 节）。
- 不让舰长给领航员改名字。那是孩子写的自由文字，要按私人文字的规则存和删（事件规格第 4 节），这一版不做。
- 不做领航员的动画（眨眼、走动）。表情是六张静止的图。
- 不把现成的角色做成领航员，也不做「自己放一张图进来」的入口。
- 不新增事件动词，不改掌握度的算法。
- 不在这份规格里定每一位长什么样。那是每位领航员自己的设计说明，照 #105 的做法出设计稿，由 Luka 和舰长看。

## 和已有规格的关系

- **内容规格、发布格式（ADR-003）**：多一种内容「领航员」，发布清单多一个键，`engine_min` 升到 2。这是长期格式的改动，要跨模型审阅。
- **事件规格、内核**：不动。「认识了谁」从 `mastery/1` 已有的 `best` 算。
- **ADR-006**：竖切片 5a 的记录是试玩记录。试玩记录如果被清掉，「认识了谁」也跟着从头算；档案里的选择按用例 11 退回。恢复演练做完以后，这个问题自然消失。
- **ADR-011（提议）**：第 5 节依赖它。它接受之前，N1、N2 照常能做。
- **`GLOSSARY.md`**：「领航员」的解释加一句「可以有好几位，舰长选一位陪他；说话的方式都一样」。给舰长看的词用「认识」，不用「解锁」「获得」「抽到」。新词「领航员舱」：看和换领航员的地方。
- **#105**：设计稿里的两个方向不再是二选一，两位都留下；要问舰长的变成「先让谁陪」。

## 拍板结果（2026-11-11，Luka）

四个问题都采纳了推荐：

1. 认识新领航员的条件是「指定的几颗星，每颗都有一次首答正确率不低于 0.8 的挑战」；认识了就不会再失去。
