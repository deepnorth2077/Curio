# 决定：学习记录里还要记什么（CURIO-013）

- 状态：提议，第 2 稿（已按独立审阅修改，见 `docs/reviews/evidence.md`；等 Luka 确认）
- 依据：事件规格第 2、3.1、3.7、6.2、6.3、8 节；竖切片 1 规格 6.4；ADR-003、ADR-004；ADR-009 增补 2；2026-11-08 基础设施审查 F1～F5（Luka 2026-11-12 提供）
- 为什么现在定：导出和恢复（下一步）做完以后，记录就开始算数。之后再补字段，补不回过去没记的东西。

## 一句话

只补三样「现在不记、以后就拿不回来」的东西，都是给已有格式加可选的部分，`schema` 仍然是 `event/2`，设备上已经存下的事件不用改。另外写下两条原则。其余的问题写明什么时候必须定。

## 定下来的

### 1. 看答案要记下来

新动词 `answer.revealed`：

| 范围 | 谁 | payload |
| --- | --- | --- |
| 尝试 | learner | `{item_id}` |

- 舰长点「看答案」时，先存好这条事件，再显示答案；存失败就提示重试，和「要个提示」走同一套流程（竖切片 1 规格 6.4）。最后一题看答案时，先存它，再产出 `attempt.completed`。
- 尝试合法性（事件规格 6.3）加第 6 条，编号最大，所以不改变「记编号最小的那条」：`answer.revealed` 的 `item_id` 在它之前已有 `item.answered`；同一个 `item_id` 最多一条；它之后不再有这道题的 `item.answered`。设备上已经存下的尝试里没有这个动词，不会因此变成不一致。
- `mastery/1` 不读它，掌握度不变：看答案之前这道题已经有一次存好的作答，首答已经定了。
- 原因：以后要分清「自己答出来的」和「看过答案以后才会的」（审查 F3）。已经完成的旧尝试可以推断出来（某道题最后一次作答是错的、之后没有答对，就是看了答案）；中途放弃的旧尝试推断不了。

### 2. 记下是哪一版判分程序判的

`attempt.started` 的 payload 加一个可选字段 `grader`：判分程序的版本，字符串，形如 `grade/1`，最多 32 个字符。

- 它由 `engine/js/grade.js` 导出一个常量。**判分的结果只要可能变**（修一个判分的错误也算），版本号就加一。它和发布包的 `engine_min`（引擎能力等级）是两回事。
- 题目和答案由 `content` 里的 `activity_version`、`content_release` 定死，作答原文在 `response` 里；加上 `grader`，就能说清当时是怎么判的，以后也能重判（审查 F2）。
- 没有这个字段的旧事件，理解为 `grade/1`。

### 3. 模拟模块里的猜测，保住误区 id

`poe.predicted` 的 payload 加两个可选字段：

- `step`：这次猜测在模块里的位置，字符串，最多 32 个字符，例如 `s1`、`s4`。
- `misconception`：所选选项对应的误区 id，字符串。没有误区时不写。

不加 `correct`：模拟里的对错是模块自己报的，不是平台判的（ADR-005），不和挑战的作答放在同一个字段里。事件规格 3.7 的对应关系不变（`predicted` 仍记成 `poe.predicted`）。每个模块每种消息具体怎么换，在竖切片 5a 的规格里按模块列表。

### 4. 新字段怎么上线：先教会所有读的程序，再开始写

设备上现在所有读事件的程序，遇到不认识的字段或动词都会拒收；带了不认识字段的 `attempt.started` 被拒收，会让整次尝试不一致。所以：

- 先发一个只是**认识**新字段、新动词的版本（`schemas/`、`kernel/js/validate.js`），等它上线；再发**写**它们的版本（`engine/`、`app/`）。两步可以是同一个任务里的两个 PR。
- 事件规格第 8 节加这一句，以后每次加可选字段都照此办理。

### 5. 两条原则

- **原事件永不改。**`item.answered` 里的 `correct` 表示「当时系统认为」。发现答案键或判分程序写错时，靠已经记下的 `response`、`content_release` 和 `grader` 重判。具体怎么改正（很可能是一条由家长或系统发出的更正事件），等第一次真的需要时再设计，先写 ADR。
- **误区 id 只是线索。**`misconception` 表示「舰长选了对应这个误区的选项」，不表示「舰长有这个误区」。任何投影和给家长看的说明都不能把一次选择写成诊断（审查第 5.2 节）。事件规格 3.1 加这一句。

## 先不定的，以及什么时候定

| 问题 | 为什么现在不定 | 什么时候必须定 |
| --- | --- | --- |
| 学习目标的稳定 ID、按年龄层次分开记掌握（F1） | 现在只有三年级的三颗星；事件里有活动 id、版本和发布，以后能查到每条作答属于哪一层 | 同一个知识点加第二个年龄层次的挑战之前 |
| 两台设备收到相互矛盾的同一条事件怎么收敛（F4） | 现在只有一台设备 | 多设备同步之前 |
| 统一的证据核对入口（F5） | 现在只有一个挑战引擎在写作答 | 第二种写作答的东西出现之前（导入工具，或者第二个引擎） |
| 首答、提示、重做对「掌握」的分量（F3 后半） | `try`、`hints_used`、`hint.used` 都已记下，算法以后可以换 | 有了一两个月的真实记录以后 |
| 题序 | 现在题序固定 | 第一次让题序随机之前，要先把题序记下来 |
| 染色体模块配对时配错的次数 | 已发布的模块把它放在 `answered` 里发出来，记不进现有动词 | 已知丢弃；那个模块出第 2 版时再看要不要记 |

- `kernel/js/validate.js`：`SCHEMA_VERBS`、`SLICE_VERBS` 都加 `answer.revealed`；认 `grader`。`poe.predicted` 本切片还不收，不改。
- `kernel/js/mastery.js`：合法性第 6 条。
- `docs/specs/events.md` 3.1、3.7、6.3 和第 8 节；竖切片 1 规格 6.4：按上面改。
- 黄金向量（受保护的路径，由另一个子 agent 先写好）：带和不带 `grader` 的 `attempt.started`；合法的 `answer.revealed`；三种违反第 6 条的（之前没有作答、同一题两条、之后又有作答）；`answer.revealed` 缺 `item_id`、多字段、`actor` 不是 learner；一次带看答案的尝试，掌握度和不看答案时相同。先确认现有反例里没有恰好拿 `grader` 当「多余的键」。

- `app/`：看答案时等存好再显示答案。

## 验收

1. 做一个挑战，有一道题答错以后看答案。答案在事件存好以后才出现；事件里有一条 `answer.revealed`；掌握度和以前一样。
2. 新尝试的 `attempt.started` 里有 `grader: "grade/1"`；设备上旧的、没有 `grader` 的事件照常读得出来，星星状态不变。
3. 原有的全部测试和黄金向量照常通过（只有第 2 个 PR 里写明的那一处断言改了）。
