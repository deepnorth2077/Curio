# 决定：学习记录里还要记什么（CURIO-013）

- 状态：提议（等独立审阅，Luka 确认）
- 依据：事件规格第 2、3.1、3.7、6.4、8 节；竖切片 1 规格 6.4；ADR-004；ADR-009 增补 2；2026-11-08 基础设施审查 F1～F5（Luka 2026-11-12 提供）
- 为什么现在定：导出和恢复（下一步）做完以后，记录就开始算数。之后再补字段，补不回过去没记的东西。

## 一句话

这一次只补三样「现在不记、以后就再也拿不回来」的东西，全部是只增不改，`schema` 仍然是 `event/2`。其余的问题写明什么时候再定。

## 定下来的

### 1. 看答案要记下来

新动词 `answer.revealed`：

| 范围 | 谁 | payload |
| --- | --- | --- |
| 尝试 | learner | `{item_id}` |

- 舰长点「看答案」、答案显示出来时记一条。同一次尝试里同一道题只记一次。
- `mastery/1` 不读它，掌握度不变：看答案之前这道题已经有一次存好的作答（竖切片 1 规格 6.4），首答已经定了。
- 竖切片 1 规格 6.4「看答案不写事件」改为写这条事件；「不改分母」不变。

原因：以后要分清「自己答出来的」和「看过答案以后才会的」，现在不记就永远分不清（审查 F3）。

### 2. 记下是哪一版程序判的分

`attempt.started` 的 payload 加一个可选字段 `engine`：开始这次尝试的外壳的引擎等级（正整数，现在是 1）。

- 题目和答案已经由 `content` 里的 `activity_version`、`content_release` 定死；再加上 `engine`，就能说清「当时用哪一版程序、按哪一版答案判的」（审查 F2）。
- 没有这个字段的旧事件，按 `engine: 1` 理解。

### 3. 模拟模块里的猜测，记成作答

模拟模块发的 `predicted` 和 `answered`（有标准答案、带误区 id 的选择），宿主记成 `item.answered`，不记成 `poe.predicted`：

- `item_id` 写成 `sim:` 开头，例如 `sim:s1`、`sim:s3.pairing`。它不对应内容文件里的任何题目。
- `mastery/1` 只看 `quiz` 尝试，所以这些作答不影响点亮；以后的错题投影也不从 `sim:` 开头的作答生成错题。
- 这样不用给 `poe.predicted` 加字段，误区 id 照样保住。`poe.predicted` 留给平台自己做的「预测 → 观察 → 解释」（#28），那里的预测没有对错。
- 每个模块每种消息具体怎么换，在竖切片 5a 的规格里按模块列表。

### 4. 答案写错了怎么改

不改旧事件，也不重新导入。规则先定下，等第一次真的要用时再实现：

- 发现某个活动版本的答案键错了，就发一个新版本的活动；旧版本在内容里加一条 `corrections`，写明哪道题、哪些作答其实是对的。
- 投影读到旧版本的作答时，按 `corrections` 重新判一次，并用新的掌握度算法版本号（`mastery/2` 之类）标明。原事件里的 `correct` 一字不动，表示「当时系统认为」。
- 奖励不受影响：第一版的奖励规则只看「做完了没有」，不看对错（事件规格 7.3）。

### 5. 误区 id 只是线索

`item.answered` 里的 `misconception` 表示「舰长选了对应这个误区的选项」，不表示「舰长有这个误区」。任何投影和给家长看的说明都不能把一次选择写成诊断（审查第 5.2 节）。事件规格 3.1 加这一句。

## 先不定的，以及什么时候定

| 问题 | 为什么现在不定 | 什么时候必须定 |
| --- | --- | --- |
| 学习目标的稳定 ID、按年龄层次分开记掌握（F1） | 现在只有三年级的三颗星，每颗一个挑战 | 第一次给同一个知识点加第二个年龄层次的挑战之前 |
| 两台设备收到相互矛盾的同一条事件怎么收敛（F4） | 现在只有一台设备 | 多设备同步之前 |
| 统一的证据核对入口：题号存在、题目齐全、类型对得上（F5） | 现在只有一个挑战引擎在写作答 | 第二种写作答的东西出现之前（导入工具，或者第二个引擎） |
| 首答、提示、重做对「掌握」的分量（F3 后半） | 先把数据记全；算法以后可以换 | 有了一两个月的真实记录以后 |

## 要改的东西

由实现者在一个任务里做：

- `schemas/event.schema.json`：加 `answer.revealed`；`attempt.started` 加可选的 `engine`。
- `docs/specs/events.md` 3.1、3.7 和第 8 节，竖切片 1 规格 6.4：按上面改。
- `kernel/js/validate.js`：认 `answer.revealed`，认 `engine`。`mastery.js` 不改。
- `engine/js/quiz.js` 和 `app/`：看答案时写 `answer.revealed`；开始尝试时写 `engine`。
- 黄金向量各加一组正反例：带 `engine` 和不带的 `attempt.started`、合法和不合法的 `answer.revealed`（缺 `item_id`、多字段、`actor` 不是 learner）；一次带看答案的尝试，掌握度和不看答案时相同。

## 验收

1. 做一个挑战，有一道题答错以后看答案。导出的事件里有一条 `answer.revealed`，掌握度和以前的算法一样。
2. 新尝试的 `attempt.started` 里有 `engine: 1`；设备上旧的、没有 `engine` 的事件照常读得出来。
3. 原有的全部测试和黄金向量照常通过。
