# ADR-003 内容发布不可变，事件引用内容版本

- 状态：提议
- 日期：2026-11-06
- 相关：CURIO-002（#4）、CURIO-007（#9）

## 背景

git 历史能回答「文件是怎么改的」，回答不了「孩子那天做题时，看到的到底是哪一版」。如果内容可以原地覆盖，旧的答题记录就会对不上：比如一道题改了答案，孩子之前的「答错」就说不清了。

## 决定

1. 知识点和活动都带 `version` 整数。改内容就加一，ID 不变。
2. 每次构建产生一个**内容发布**（ContentRelease）：
   - `release_id`，格式 `rel_<日期>_<内容哈希前 8 位>`；
   - 收录的每个知识点、每个活动的 ID 和版本；
   - 每个文件的 SHA-256，以及整个发布的内容哈希。
3. 发布一旦生成就**不可变**。要修订，就产生新版本和新发布。
4. 每条学习事件至少记录 `activity_version` 和 `content_release`。
5. 「回滚」只是把「当前生效的发布」指回上一个，不删任何东西、不改任何事件。
6. 历史发布永久保留，可以随时单独打开预览。内容是文本，十年也占不了多少空间。
7. 同一份内容重复构建，必须得到同样的哈希（可复现构建）。

## 放弃的方案

- **只靠 git 提交号**：一次提交里可能有还没发布的草稿，而且孩子的设备不知道 git。
- **允许热修改已发布内容**：省事，但历史记录会失真。

## 后果

- 孩子做过的每件事，都能查到当时的内容版本（这是 Luka 要验收的六件事之一）。
- 设备上会缓存当前和最近几个发布，断网时也能用。
- 构建管线（CURIO-007）要负责生成发布清单和哈希。

## 待拍板

无。
