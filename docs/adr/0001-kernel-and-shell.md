# ADR-001 平台内核与产品外壳分离

- 状态：提议
- 日期：2026-11-06
- 相关：CURIO-001（#3）、`docs/domain.md`

## 背景

Curio 要用十年。这十年里，孩子从三年级长到高三：界面风格、叫法、主题都会变，可能会加学科，也可能多一个孩子。原型里，「星图」「维修舱」这些产品概念和数据混在一起。如果底层的数据和同步也按这些产品概念来设计，以后每改一次界面，都可能要迁移历史数据。

## 决定

1. 平台内核只认这些通用对象：Family、Learner、Caregiver、Device、KnowledgeNode、ActivityDefinition、ContentRelease、Attempt、LearningEvent、Question、RepairTicket、Plan、Reward、Projection。定义见 `docs/domain.md`。
2. 星图、知识地铁、维修舱、信号站、航线、宝可梦主题、手绘风格，以及每个具体学科，都属于**产品外壳**。外壳读写内核对象，但不进入最底层的身份和同步语义。
3. 判断一样东西属于内核还是外壳，只看一条：**把它换掉以后，孩子的历史数据还能不能原样读出来。**
4. 只支持单家庭，不建设多租户；但每条事件从第一天起就带 `learner_id` 和 `device_id`。

## 放弃的方案

- **直接按产品概念建模**（星球表、维修舱表）：写起来快，但改界面就得迁数据。
- **通用多租户平台**：给一个家庭用，代价太大，也不是目标。

## 后果

- 原型里的「维修舱」在内核里叫 RepairTicket，「信号站」叫 Question，「航线」叫 Plan。界面怎么叫都行。
- 内核对象的格式改动，必须走新的 ADR，并带迁移脚本。外壳可以随时改。
- 多出的 `learner_id`、`device_id` 字段，几乎没有成本。

## 待拍板

- 除了你之外，还有别的家长（例如孩子妈妈）需要看进度、确认兑换吗？这决定 Caregiver 是一个还是多个。
