# 架构决策记录（ADR）

每份 ADR 记一个影响长期的架构决定：当时的背景、决定了什么、放弃了什么、会带来什么后果。

ADR 一旦接受，**决定本身**就不改写。要推翻某个决定，就写一份新的 ADR，在里面注明「取代 ADR-00x」，旧的那份状态改为「已被取代」。这样十年后还能查到当初为什么这么做。

后续规格把一个已接受的决定写得更具体、或者纠正其中的细节，而决定的方向不变时（例如 ADR-004 的奖励唯一键随事件规格细化），可以在原 ADR 里直接修订：开头加一行「修订：日期，随哪个 PR，改了哪几节」，并在那个规格里列出修订内容。

什么时候该写 ADR：同时满足三条才写：难以撤回；不交代背景，后来的人会奇怪「为什么这样做」；确实在几个方案之间做了取舍（ADR-009 第 3 条）。缺一条就写进规格或文档。
