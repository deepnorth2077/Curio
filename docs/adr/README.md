# 架构决策记录（ADR）

每份 ADR 记一个影响长期的架构决定：当时的背景、决定了什么、放弃了什么、会带来什么后果。

ADR 一旦接受，原文就不改写。这样十年后还能查到当初为什么这么做。改动分三种：

- **直接改**：只限错别字、坏链接，以及不改变任何规则含义的措辞澄清。
- **增补**：会改变规则含义的，例如唯一约束、ID、接口、兼容性、默认行为、数据怎么解释，在原 ADR 文末追加「增补 N」，写明它取代原文的哪几条。原文一字不动，开头加一行说明有增补。增补和新 ADR 走一样的流程：外部模型审阅，Luka 确认。
- **取代**：决定的方向变了，就写一份新 ADR，注明「取代 ADR-00x」，旧的那份状态改为「已被取代」。

什么时候该写 ADR：同时满足三条才写：难以撤回；不交代背景，后来的人会奇怪「为什么这样做」；确实在几个方案之间做了取舍（ADR-009 第 3 条）。缺一条就写进规格或文档。
