# ADR-005 活动宿主是唯一的权限边界

- 状态：已接受（2026-11-06，经外部模型复审修订）
- 日期：2026-11-06
- 相关：CURIO-004（#6）、CURIO-005（#7）

## 背景

自定义实验是实现 AI 写的代码，平台不能假定它可信。原型只检查了两件事：消息是不是来自这个 iframe，契约版本对不对。它没有运行状态，也没有逐条校验消息内容。另外，原型里每个模块都会从 Google Fonts 加载字体，违反了契约里「不依赖外部 CDN」的规定。

## 决定

1. **沙箱**：自定义活动放在 `sandbox="allow-scripts"` 的 iframe 里，**不**给 `allow-same-origin`。模块拿不到平台的存储、cookie，也碰不到页面。
2. **断网**：宿主给每个模块注入内容安全策略（CSP）`default-src 'none'`，只放行内联脚本、内联样式，以及 `data:`、`blob:` 形式的图片和字体。模块即使想联网也连不出去。
3. **运行状态机**：每次运行有唯一的 `run_id` 和 `attempt_id`。状态依次是：加载 → 就绪 → 运行（实验还分预测、观察两个阶段）→ 完成或中止。
4. **逐条校验消息**。以下任何一条不满足，宿主就丢掉这条消息，并记一条契约警告：
   - 来自当前 iframe；
   - 契约版本对；
   - 带着本次运行的 `run_id`；
   - 当前状态允许这种消息（例如完成之后不能再发 `complete`）；
   - payload 符合这个动词的 schema；
   - 动词在 manifest 的 `emits` 里声明过。
5. **资源配额**。具体数值在 CURIO-005 里定，并写进契约：
   - 单条消息的大小上限（例如 64 KiB），超过的丢弃；
   - 消息频率上限（例如每秒 50 条），超出的部分丢弃，只记一条警告；
   - 每次尝试的事件数上限，防止刷爆存储；
   - 每次运行的契约警告数上限，超过后只记一条汇总；
   - `resize` 的高度范围和频率上限。
6. **超时**：模块在规定时间内没有 `ready`，或者长时间没有心跳，宿主就中止这次运行，并给孩子看得懂的提示，让孩子可以重新开始。
7. **AI 请求**：只能由宿主按 manifest 里声明的能力，转发给 AI 网关。模块永远拿不到密钥。
8. **不加载任何外部资源**：宿主和模块都不能隐式加载外部的字体、脚本或图片。字体随项目自带，只保留用得到的字形。

## 这套边界能保证什么，不能保证什么

**能保证**：模块读不到孩子的数据、AI 密钥和平台存储；连不上网；它发出的每条消息都经过校验，写不出不合格式、数量超限的事件。

**不能保证**：
- 模块里的死循环或大量计算，可能卡住它所在的线程。浏览器不一定把沙箱 iframe 放到单独的进程里，这时整个页面都可能变慢甚至卡住。宿主没法可靠地从外面打断一个已经卡住主线程的死循环，只能在恢复响应后发现心跳中断、提示重新加载。
- 内存占用过大，可能导致页面崩溃。

这两类问题靠审核和测试台（CURIO-004 要包含异常运行和资源消耗的测试）来拦，而不是靠运行时边界。

## 放弃的方案

- **信任模块，只靠审核把关**：审核会漏，代码一多就更会漏。
- **用 Web Worker 跑模块**：隔离更彻底，但画不了界面。

## 后果

- 坏模块读不到数据、连不上网、写不出非法事件；但卡死或耗尽资源仍有可能，要靠测试台把关。
- CURIO-004 的测试台可以直接按这套状态机和配额写自动测试。
- 原型里的宿主要重写（CURIO-005），字体要改为随项目自带。
