# ADR-002 结构化内容优先，自定义 HTML 是例外

- 状态：提议
- 日期：2026-11-06
- 相关：CURIO-002（#4）

## 背景

原型里的「分蛋糕小挑战」把题目、选项、答案、误区全写在 JavaScript 里。这违反了「内容即数据」的原则，带来三个问题：

- schema 只能校验 manifest，查不到题目本身对不对；
- 「每个误区都有题针对」没法自动检查；
- 改一道题就要改程序，还得重新派给实现 AI。

如果每个普通测验都是一个独立的 HTML 小程序，十年下来会积累几百个难以维护、风格各异的小程序。

## 决定

1. **通用活动用「结构化内容 + 平台共享引擎」。**`explain`（讲解）、`quiz`（挑战）、`hint-ladder`（提示阶梯）、`reflection`（反思）这几类，内容是数据文件，由平台自带的引擎显示和判分。
2. **题目的每个部分都是数据**：题干、配图、选项、正确答案、每个错误选项对应的误区 ID、三级提示、答对和答错时的反馈。答案的判定方式也是数据，例如「分数要约分后比较」「数字允许 ±0.01 的误差」。
3. **配图**用两种方式之一：平台内置的参数化图形（例如 `pie(4, 1)` 表示一个圆平均分成 4 份、涂 1 份），或者经过净化的静态 SVG 文件（不含脚本）。
4. **只有通用引擎表达不了的模拟和实验**（例如小孔成像），才用「manifest + 沙箱 HTML」。它们同样带版本，同样进入发布包。
5. 每种通用活动类型各有一份 schema 和自动测试。

## 放弃的方案

- **所有活动都写成 HTML 小程序**：灵活，但没法统一校验、迁移和改版。
- **只用结构化内容，不允许自定义 HTML**：实验和模拟做不出来，而它们正是激发好奇心最有效的部分。

## 后果

- 改一道普通题，只改数据文件，不用改程序，也不用重新派发。
- 「每个误区都有题针对」可以由 CI 直接从题目数据里算出来，不再依赖 manifest 里的声明。
- 平台要先做好这几类通用引擎（CURIO-005），实现 AI 的工作从「写小程序」变成「写题目数据」和「写实验」。
- 原型里的分数挑战，要改写成结构化数据。

## 待拍板

无。
