### 1. “按最高档审”会丢掉其他维度的必要检查

- 严重程度：**阻断**
- 位置：`docs/adr/0009-engineering-practices.md` 增补 1“决定”第 1 条；`docs/collaboration.md` 风险表；`GLOSSARY.md`“风险档”。

### 2. D 档按文件或任务名称放行，可能放过内容错误和数据损坏

- 严重程度：**阻断**
- 位置：ADR-009 增补 1 的 D 档；`docs/collaboration.md`“Claude 自己的改动”“CI 检查什么”。
- 问题：“文档”“小工具”“重新生成内容包和试玩页”不能直接代表低风险。发布构建器、恢复脚本可以很小；规范性文档会改变后续实现；内容重建可能更换输入、生成器或题目答案。现有 CI 清单覆盖结构、引用、部分提示泄漏等，未承诺验证所有科学事实。符合 schema 的错误答案仍可能进入内容包。代码容易回退，也不能说明已改写的孩子数据可以恢复。

| 改动 | 建议路由 | 判断依据 |
| --- | --- | --- |

### 3. 同一模型的新会话不等于跨模型审阅，独立核对还需独立证据

- 严重程度：**重要**
- 位置：ADR-009 增补 1 的 A/B 档与“风险一”；`docs/collaboration.md`“Claude 自己的改动”。
- 问题：A 档先要求“不同的模型”，随后允许“没参与过的 Claude 会话”，混合了人员角色独立和模型来源不同两个概念。子 agent 可以换上下文，但仍可能接受同一错误前提。B 档只在学科首个知识点跨模型核对，不能覆盖后续新概念、新模拟方式或模型/提示词变化。孩子试玩可以暴露不好用，却不能承担科学正确性验证。
- 建议：明确两类证据：普通独立审查是“未参与制作、先从规格与验收标准独立判断”；跨模型核对则必须实际使用不同模型来源。对于 A 中的数据迁移、恢复、权限及长期契约语义，保留真正的跨模型审阅。其他 A 事项若允许新 Claude 会话，明写例外及补偿验证，不称其为跨模型。

  B 的核对者应能查到实际出处，而非只认可制作者给出的解释。最低成本做法是保留“内容位置—结论—出处章节/页码或可复算依据—适用边界”。新增概念、新类比、新模拟模型、来源冲突、核对者不确定、模型或核心提示词变更时，再触发跨模型核对。学科首个知识点可以保留为额外校准，不作为唯一触发条件。

  每个里程碑可合并一次小样本抽查，覆盖普通内容与高不确定内容；发现错误后按共同来源、模板或算法扩查。无需恢复每个活动来回传话。

### 4. B 档“逐句对出处”还未覆盖科学含义的完整载体

- 严重程度：**重要**
- 位置：ADR-009 增补 1 的 B 档；`docs/standards.md`“给孩子看的内容”；`AGENTS.md` 原则 5。
- 问题：B 已包含错误选项和配图数量，这是对的；但逐句核对仍可能漏掉图形关系、动态模拟、判分等价性、反馈分支和生成题。比如文本正确，切分图形却面积不等；画面比例错误；等值分数被判错；“总是成立”的反馈遗漏适用条件。这类错误不会靠句子出处或试玩自动消失。
- 建议：B 以“孩子可能形成的结论”为单位，覆盖文字、图形、动态行为和判分。数学题使用独立手算值与等价答案/边界例；模拟列明适用范围和简化假设；错误选项核对其确实错误、误区映射正确、不会出现多个合理答案。运行时生成题仍执行 AGENTS 原则 5，不能用一次 PR 核对替代逐次生成校验。

  已审且未变的内容允许沿用证据；审核变化部分及其受影响关联，不必每次全文重新查证。共享活动变化应列出所有受影响知识点。

### 5. 取消“两条线”长报告，不应连同最低验收检查一起取消

### 7. 不操作 git 仍可能覆盖工作文件，必须定义子 agent 的写入范围

- 严重程度：**重要**
- 位置：ADR-009 增补 1“决定”第 2 条；`docs/collaboration.md`“只有一个人在写 git，不会冲突”及“一件事的完整流程”；`AGENTS.md`“协作方式”。
- 问题：多个子 agent 写同一个工作目录，即使都不执行 git，也可能相互覆盖文件；审查期间文件继续变化，还会导致审的是旧版、合入的是新版。当前“子 agent 产出直接写 Claude 工作区”的描述没有路径分配、完成边界或只读审查要求。并行读错正在修改的规格，也不需要发生 git 冲突。
- 建议：默认一个任务一个隔离输出目录，或明确互不重叠的文件所有权；基于冻结的提交/规格快照执行。子 agent 不写主工作区共享文件，维护者逐个整合；审查者只读冻结产物。同文件冲突由维护者串行解决，并重查受影响部分。先用临时目录即可，不必为了这次优化引入复杂的多工作树系统。

### 8. 可以取消传输哈希，但还缺“实际审了哪一版”的绑定

- 严重程度：**重要**
- 位置：ADR-009 增补 1 子 agent 留档要求；`docs/collaboration.md` 提交署名、squash 合入与收货哈希核对；`AGENTS.md` 审核结果要求。
- 问题：设计说明、审查记录和 `Implemented-By: <模型> 子 agent` 能说明分工，但不足以证明最终内容就是被审核的内容。`Reviewed-By: Claude` 也不能区分事实核对、体验审核和整合者自检。squash 后若只把角色信息放在被压缩的单个提交里，主线追溯会依赖额外历史。
- 建议：不要求子 agent 再算每个文件的 SHA-256。使用 Git 已有的提交/树身份，给每个 PR 留一份轻量记录：任务/issue、基准提交、规格和契约版本、实现者和核对者的实际模型标识、各自范围、被审代码提交或树、结论、证据链接、未解决问题。模型版本不可见时写“未提供”，不要猜。

  最终整合如修改内容、代码或规格，重新检查受影响范围；只新增审查记录等元数据时记录差异即可，避免“记录自己的哈希”形成循环。合入时保存 PR、被审对象与 squash 提交的对应关系，比较适用文件差异，并确保最终提交消息保留必要署名。

  十年可追溯还依赖仓库和证据被备份。可复算依据、关键来源章节及必要短摘录放在版本化记录里；大型截图不必每轮永久提交，保留被接受的代表样板和重要缺陷证据即可。

### 12. 好奇心应观察探索行为，不宜变成点击率或固定提问次数
