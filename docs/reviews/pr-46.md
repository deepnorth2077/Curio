## 第 1 轮 · 审阅者 GLM-5.3 · 基于提交 c9a438e

### 结论

可以合入——两处核心改动（assets 目录用 `parts[2] == node_id` 精确锚定、`content-template.md` 入 PROTECTED）没找到可绕过或误伤的写法，三个新测试分别能锁住对应的回退；但 `prompts/` 的保护仍是黑名单式，`review.*.md` 等任务文件还漏着，另有 rename/删除缺回归测试、SVG 白名单扫描范围偏窄三个重要项，建议合入后立刻在下一个 `arch/` PR 里补上（都是几行的改动）。

### 问题

#### 1. `prompts/` 的保护仍是黑名单式，`review.*.md` 和已合入的 `act.*.md` 对普通分支不设防

- 严重程度：重要
- 位置：`tools/ci_checks.py` 第 59 行 `PROTECTED` 列表
- 问题：本 PR 把 `content-template.md` 加进 PROTECTED，意图显然是「Claude 写的模板/任务文件只能 `arch/` 改」。但 PROTECTED 在 `prompts/` 下仍只列三个模板。按第 387 行的逻辑，`feat/`、`fix/`、`chore/` 分支的放行条件是 `not match(p, PROTECTED) and not p.startswith("content/")`，于是 `prompts/review.kp-assets.task.md` 这类审阅任务提示词、以及已合入的所有 `prompts/act.*.md`，任何普通分支都能改。更别扭的是：`kp/` 分支改 `prompts/act.*.md` 还要过 targets 校验（只能改自己活动的），`feat/` 分支改**任何**活动提示词反而零约束。任务文件被错分支改掉后，`make_task.py` 生成的派发内容随之被污染，且没有任何测试能发现。
- 建议：改成白名单语义——PROTECTED 加一条 `prompts/*`（fnmatch 的 `*` 会穿透 `/`，能覆盖整个目录树），同时把 `kp/` 分支第 367 行的放行条件改成对 `prompts/act.*.md` 豁免 PROTECTED，例如：`ok = (p.startswith("content/") and not match(p, PROTECTED)) or fnmatch.fnmatchcase(p, "prompts/act.*.md")`（直接加 `prompts/*` 而不改这行会把 kp 分支改自己活动提示词的正常工作流也拦死）。补两个测试：`feat/` 改 `prompts/review.x.md` 报错；`kp/<id>` 改自己活动的提示词仍通过。

#### 2. rename 和删除路径没有回归测试

- 严重程度：重要
- 位置：`tools/tests/test_ci_checks.py` 新增的 3 个测试
- 问题：现在的实现恰好是对的——第 327–328 行把 rename 的新旧路径都收进 `changed`，删除（`D`）的路径也在，所以「把别人配图改名到自己目录下」「删别人的配图」都会被拦；「删自己的旧配图」也正确放行（若该图仍被活动引用，会被「svg 配图引用的文件不存在」拦下，分工合理）。但这些行为没有测试锁定：将来重构时把 `changed` 改成只看新路径、或把 `D` 排除掉，现有测试全绿。另外 `-M` 相似度不足时 rename 会被 git 拆成 D+A，这条路径同样无测试。
- 建议：补 4 个用例：① `kp/N2` 把 `content/assets/N1/a.svg` 改名为 `content/assets/N2/a.svg` → 报错；② 同一场景换成低相似度内容（拆成 D+A）→ 报错；③ `kp/N2` 删除 `content/assets/N1/a.svg` → 报错；④ `kp/N2` 删除/改名 `content/assets/N2/` 下自己的文件 → 通过。

#### 3. SVG 白名单只扫 `content/assets/`，活动目录里的 svg 不检查

- 严重程度：重要
- 位置：`tools/ci_checks.py` 第 576–578 行（figure.src 只查存在）、第 587–590 行（扫描范围）
- 问题：figure 的 `src` 不限制在 assets/ 下，只查 `(repo / src).is_file()`。`kp/` 分支对自己活动目录有完整写权限（`content/activities/<act>/` 下 targets==[node_id] 即可），把含 script、外链等白名单外内容的 `content/activities/<act>/x.svg` 写进去并在题目里引用，SVG 白名单扫描（`content/assets/` 下的 `rglob("*.svg")`）看不见，未审查内容可进发布物。
- 建议：二选一：把白名单扫描范围扩成「所有被 figure 引用的 svg + `content/assets/` 全部」；或在引用检查里限制 `src` 必须以 `content/assets/` 开头（这也顺带堵住 symlink 之类绕过 `content/assets/<id>/` 锚点的花活）。注意核对存量活动的 src 是否都在 assets/ 下，避免上线即红。

#### 4. 文档「题目和文字」行写了「字数」，脚本里没有对应逻辑

- 严重程度：建议
- 位置：`docs/collaboration.md`「CI 检查什么」表
- 问题：`ci_checks.py` 全文只有用词（「学习」）检查，没有字数检查（第 190 行的 `len(items) < 5` 是题数不是字数）。若字数约束实际由 schema 的 maxLength 之类承载、随 schema 校验生效，表格把它与用词并列为独立检查项也容易误读；内容规格 3.4/3.7 未随附，无法核实出处。
- 建议：改为「字数约束由 schema 承载（内容规格 3.x）」或直接删掉，避免文档声称了不存在的检查。

#### 5. 文档与代码的几处小偏差

- 严重程度：建议
- 位置：`docs/collaboration.md`「CI 检查什么」表
- 问题：①「ID 检查」行写「没有删除、改名或改动已有的 ID」，但带「越界-已批准」标签时删除/改名是 warn 放行，表格没提（地盘检查的 override 在表后段落里有说，这行漏了）；②「引用」行只写了 activities/targets 双向一致，代码第 480 行连 `related` 引用存在性也一起查；③知识点卡同样走 `knode.schema.json` 校验，「形态和规格校验」行只提了活动。
- 建议：各补半句即可。其余各行（含「选择题提醒」对应 warn、「只算错误选项和 `common_wrong`」的覆盖口径、「至少 5 题」等细节）与代码逐行核对过，一致。

#### 6. fnmatch 大小写在本地和 CI 上行为不一致

- 严重程度：建议
- 位置：`tools/ci_checks.py` 第 110 行 `match()`、第 367 行、第 361 行 `rglob`
- 问题：`fnmatch.fnmatch` 走 `os.path.normcase`，Windows 上大小写不敏感：本地跑（脚本文档鼓励本地跑）时 `prompts/ACT.x.md` 会被当成活动提示词放行、`prompts/Content-Template.md` 反而会被 PROTECTED 拦截，Linux CI 上结论相反。第 361 行 `rglob(f"{node_id}.yaml")` 在 Windows 上也不区分大小写——分支名里知识点 id 大小写写错时本地过、CI 拦。最终裁决在 GitHub Actions（Linux）上，风险是本地「通过」与 CI 结论打架、浪费来回。
- 建议：统一改用 `fnmatch.fnmatchcase`；并在文档里提醒本地通过不代表 CI 通过。

#### 7. 自己的 assets 目录里可放任意类型文件

- 严重程度：建议
- 位置：`tools/ci_checks.py` 第 374–377 行
- 问题：规则只锚定目录（`parts[2] == node_id`）不限扩展名，`notes.txt`、html 都能进自己的配图目录，可能跟着发布物走（取决于构建器是否整目录拷贝）。自己的地盘，危害小。
- 建议：可选：把 `parts[3:]` 限制为 `.svg` 结尾，或至少在 `docs/workflow.md` 写明配图目录只放 svg。

### 其他

- **绕过尝试均未成立**（作为「可以合入」结论的依据）：前缀近似（`kp/a.b` 改 `content/assets/a.b-c/cake.svg`）被 `parts[2] == node_id` 精确相等拦住，测试里 `N2x` 负例已锁定；`..` 与 glob 字符既进不了 git 路径（refname/路径规范），即使进了也会被 PATH_SEGMENT 检查拦；大小写错位的目录名（`content/assets/ABC/…`）在 Linux 上过不了 `==`，若与已有路径只差大小写还会被第 436 行的重复路径检查拦下；深层子目录（`content/assets/<id>/parts/half.svg`）逃不出 parts[2] 锚点，正例测试已覆盖；rename 新旧路径、D+A 拆分都进 `changed`，逻辑上都能拦（缺的只是测试，见问题 2）。
- **误伤方向也查过**：正常流程（卡片先以 draft 合入，`kp/` 分支再加活动与配图）不卡；即使卡片只在本分支新建，存在性检查用工作区 `rglob` 也能找到；删自己的旧配图放行；rename 自己目录内的配图新旧路径都合法。
- **symlink**：`kp/` 分支可以在自己 assets 目录提交 symlink（git mode 120000），路径检查会放行；`Path.rglob` 不穿透 symlink 目录，SVG 扫描扫不到，而 figure.src 的 `is_file()` 会跟随。实际危害有限（引用到的仍是 assets 树内被扫过的文件），若想收紧可在路径规则里拒绝非普通文件。
- 测试断言 `sum("不能改这个文件" in …) == 3` 依赖错误文案精确计数，将来改措辞会误报，建议改成按文件路径断言。
