# PR #225 舰长资料规格独立审查

独立审查由未参与写规格的 Claude Sonnet 子代理（本会话的规格审查代理）完成，只读，对照 `AGENTS.md`、事件规格、备份规格、`event.schema.json`、`kernel/js/validate.js`、`app/` 的存储、备份、恢复、家长页和 `tools/backup_ref.py`。第 1 稿结论「改后通过」，维护者核对了三条必须改的证据后出第 2 稿。

| 核对项 | 第 1 稿的问题 | 第 2 稿的处理 |
| --- | --- | --- |
| 读程序是否要改 | 「备份恢复一个字不用改」不属实：`validate.js` 的 `SLICE_VERBS` 是摄入白名单，`checkVerb` 默认要求 `attempt_id`、`content` 和 learner；`backup_ref.py`、两处测试清单写死动词；`session.js` 的 `assemble` 只会组装活动事件；`store.js` 要加 `caregiver` 键 | 第 7 节列出全部改动，按事件规格「先教会读的程序，再写」拆成两个 PR；写明旧版恢复时记 `not_yet_known` |
| 干净设备 | `isClean` 要求全空，先存资料再恢复别的 learner 的备份会被 `other_learner` 拒绝，而「还没填」提醒正好诱导这个顺序 | 第 4 节：干净设备上提示先恢复、保存前二次确认、不显示提醒；测试接缝加一例 |
| 日期 | 事件规格第 1 节本地日期固定 UTC+8，第 1 稿用设备时区 | `grade` 收时间戳，按 UTC+8；手算例子加 UTC 边界 |
| 排序与时钟 | 「最大生效」合规但应写进事件规格 6.4；投影缺 `algorithm_version`；时钟走错的语义发布后改不了 | 加 `rev`，先比 `rev` 再比排序键；profile/1 写进 6.4，输出带 `algorithm_version` 和 `conflicts` |
| payload 细节 | `textbooks` 能否为空没写；扩展枚举和范围对旧版是 `quarantined_new` | 写明 `{}` 合法；扩展一律先读后写 |
| 其他 | 8 月选年级有歧义；`firstEventAt` 会提前 | 下拉标出学年；写明提醒从资料时间算起 |

没问题的部分：手算的年级例子全对；备份文件格式、指纹、可读导出按原文处理，不用改；掌握度和探索进度的投影容得下不带 `attempt_id`、`content` 的事件；`caregiver` ID 不进备份没有影响；仍是 `event/2`，不需要升级器。
