# PR #190 知识点目录独立审查

独立审查由未参与测试和实现的 Codex 子代理完成。审查对照 #188、目录规格和 #184 家庭试玩原型。初审发现一处知识点分支门禁回归，修复后复核通过。

| 核对项 | 复核结果 |
| --- | --- |
| 首版目录 | 直接运行 #184 提交里的原型数据合并逻辑，读取它的 93 个现行点和 9 个旧占位。按 ID 对照，新目录的名称、年级、主题、单元、87 条前置关系以及 9 个旧名的接替目标全部吻合。23 张同 ID 课程卡中，3 张已发布、20 张是草案，另有 70 个现行点尚无卡。 |
| 先红验收 | 在只含验收的提交 `3598b90` 重跑 Python 目录测试，得到 24 项预期失败。实现后的目录、发布包和外壳读包用例通过，首批 5 个测试与向量文件逐字节保留。 |
| ID 和旧记录 | 通过临时仓库对比主线。旧 ID 消失、已退役 ID 重新使用、年级或主题变化、接替者缺卡和无效前置均被门禁拦住；点从现行表移到退役表可通过。 |
| 发布与备份 | 实际构建的清单带 3 张已发布卡和目录的 YAML、JSON 摘要。改目录引起发布 ID 变化，旧包仍通过外壳读包。将实包清单和一份无目录的旧清单一起交给正式备份代码，执行 gzip 加密导出、解密读回，两份清单原文逐字节一致。 |
| 预览 | 分别构建有目录和无目录的预览。正式预览包多出可选目录字段，原有课程和活动相同；试玩包里的 23 条星座归属仍由原试玩清单给出。 |

## 修复记录

在临时仓库的 `kp/math.number.new` 分支中同时添加一张卡和它的目录条目时，初版 CI 将 `content/catalog/points.yaml` 判为越界；单独添加卡又会违反目录完整性。修复后，知识点分支可以登记或维护自己的现行条目并提升目录版本。复跑分支正反例，新增本卡、更新本卡均通过，夹带其他点或退役条目、只改版本号，以及修改主线已登记年级均被拒绝。
