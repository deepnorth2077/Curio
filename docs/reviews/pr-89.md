## 第 1 轮（b9a129b，61 条）

结论：期望值全部正确（审查者按规格独立换算毫秒时间戳，没有采信 `why` 字段）。没有阻断项；5 条重要、12 条建议，都是覆盖和比较逻辑的缺口。

处理（全部采纳，提交 454e4e6）：
- 补 31 条用例：错误响应的 CORS 头、没有 Origin、ping 不受锁定影响、预检不论路径、路由→自检→大小的顺序、自检写日志、单价四个、`POST /v1/usage`、Bearer 小写、按字节算请求体、去空白后再发、第一条消息是领航员说明、`context` 为 null 或字段非字符串、锁定边界 t0+1799.999、`daily_cap` 先于 `monthly_cap`、用量不受上限影响、日和月滚动、`fen_month` 整除、两种 `Retry-After` 取整和跨年、上游空回答、没有 choices、上游 429、只缺一个缓存字段。
- 脚本：密钥、口令、盐、哈希在每条用例的存储、日志（含 stdout/stderr）、响应里都不能出现；错误响应体整体比较；有 JSON 就查 Content-Type；给了上游回应就必须调用；可以检查最后一条消息和第一条消息的角色。
- 规格补写（第 2～4 节）：单价逗号旁空格忽略、错误响应也带 CORS、Bearer 不分大小写、`context` 必须是对象、请求体形态、空回答算 `upstream`、只缺一个缓存字段算 0。第 1 条（`thinking`、`stream` 写死）按 DeepSeek 官方文档的 `thinking: {"type": "disabled"}` 写进规格。
- 第 8 条（失败时 `storage_absent`）保留，规格写明「没有用量就不写存储」。

新增的 31 条由实现子 agent 逐条跑，有异议在交付说明里列出，整合时再判。
