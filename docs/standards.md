# 规范

审核时「规范」这条线对照的标准（ADR-009 第 7 条）。另一条线「规格」对照的是 issue 和 `docs/specs/`。

这里只写**判断题**，也就是自动检查替代不了的东西。机械的规则（文件放在哪、ID 格式、禁用词、交付包格式）由 `tools/ci_checks.py`、`tools/intake.py` 和 schema 负责，不在这里重复。发现一种错误反复出现、而且能写成检查时，就写成检查，并把这里的对应条目删掉。

## 所有交付物

- **用术语表的词**（`GLOSSARY.md`）。同一个意思只用一个词，标识符、注释、界面文字都一样。
- **只做规格要的**。没被要求的参数、开关、扩展点不加，等真正需要时再加。
- **名字说清用途**。读名字就知道它装的是什么、做的是什么；想不出准确的名字，通常说明设计还没想清楚。

## 代码

- **不用框架，不需要打包**（ADR-008）。浏览器里用原生 ES 模块，类型用 JSDoc 标注。这一条以后会写成自动检查，写好后从这里删掉。
- **一起变化的东西放在一起**。同一类改动反复散落在很多地方、却说不出共同的原因，说明该放在一起的东西被拆散了；反过来，一个文件为好几种不相干的原因被修改，说明该拆开。一个竖切片本来就要跨几层，改到多个文件是正常的，不算这个问题。
- **领域概念有自己的类型**。例如「发布 ID」不只是一个字符串，「本地日期」不只是一个时间戳。
- **纯函数优先**。投影、规则、校验写成纯函数：输入相同，输出就相同，不读时间、不读随机数。

## 测试

- **测在接缝上**：只通过任务文件里定好的公开接口检查行为，不测内部实现，不检查私有函数，不统计函数被调用了几次。
- **期望值来自独立来源**：手算的字面值、规格里的例子，不能用被测代码的算法再算一遍。
- **测试名说「什么」，不说「怎么」**：例如「同一兑换申请确认两次只扣一次」。
- **正反都有**：每条规则至少一个应该通过的例子和一个应该失败的例子（AGENTS.md 原则 8）。

## 给孩子看的内容

- **科学上准确**。数学上对的答案不能判错（例如等值分数）；简化讲法不能和以后要教的内容矛盾。
- **先教后用**。题目、提示里用到的词，讲解里要先出现。
- **一句话只说一件事**。题干一次只问一个问题。
- **提示是梯子**。一条比一条更具体，前一条没帮上忙，后一条才多给一点。最后一条有没有说出答案，数字题、分数题由 CI 检查，选择题由 CI 提醒、审核者判断（内容规格 3.4）。

## 代码坏味道（只作提醒）

这些是 Fowler《重构》第 3 章列出的常见问题，审核时只标为「可能有」，严重程度默认是「建议」，由审核者判断。和上面的仓库规范冲突时，以仓库规范为准。「可以考虑」一列只是常见的改法，不是必须照做的要求。

| 坏味道 | 是什么 | 可以考虑 |
| --- | --- | --- |
| 名字说不清 | 名字看不出装的是什么、做什么 | 改名；起不出好名字，就回头理一理设计 |
| 重复 | 同一段逻辑在几处出现 | 抽出来，几处共用 |
| 依恋别人的数据 | 一个函数用别的对象的数据比用自己的还多 | 把函数挪到数据那边 |
| 结伴出现的数据 | 几个参数总是一起传 | 合成一个类型 |
| 拿基本类型代替概念 | 用字符串、数字表示一个领域概念 | 给它自己的类型 |
| 重复的分支 | 同样的 `switch` 或一串 `if` 出现在好几处 | 合并成一张对照表，或者用多态 |
| 霰弹式修改 | 同一类改动反复散落在很多处，没有共同的原因（一个竖切片跨几层不算） | 把一起变化的东西放到一起 |
| 发散式修改 | 一个文件为几种不相干的原因被修改 | 拆开 |
| 过度设计 | 为规格里没有的需求加的抽象 | 删掉，等需要时再加 |
| 长链调用 | `a.b().c().d()` 一路点下去 | 在第一个对象上提供一个方法 |
| 中间人 | 一个函数几乎只是转手调用 | 去掉它，直接调用 |
