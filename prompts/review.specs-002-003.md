# 审阅任务（第 2 轮）：「好奇号」的内容格式规格和事件格式规格

## 背景

「好奇号 Curio」是一个家庭自用的理科探索网站，陪一个孩子从 2026 年小学三年级用到 2036 年高三，覆盖数学、物理、化学、生物。目标是「基础设施级」：数据要用十年，能多设备离线使用、联网同步，能随时换算法重算，任何一点能量、任何一次答题都查得到来历。

仓库只有一个维护者 Claude。其他 AI 只按 Claude 写的任务文件做实现，交付回来由 Claude 审核、整合。Claude 自己写的架构改动不能自己审，所以请你来审。

这是 PR #21 的**第 2 轮**审阅。第 1 轮由另一个模型审阅，提了 12 条意见（其中 6 条阻断），Claude 逐条做了回应和修改。下面的「审阅记录」里有第 1 轮意见的原文和 Claude 的回应。规格合入以后，实现 AI 会**完全照着它们**写 schema 和代码，所以这里的含糊、矛盾和漏洞，都会被原样实现出来。

## 你的角色

资深的数据架构师，熟悉事件溯源、离线优先的多设备同步、内容版本管理、隐私数据删除和 JSON Schema；同时关心一个三年级孩子实际用起来的情况。请挑刺，不要客气。你可以不同意第 1 轮的审阅者，也可以不同意 Claude 的回应。

## 请重点看这些问题

1. **第 1 轮的问题真的改好了吗？**逐条对照审阅记录和现在的规格，指出没改到位、改出新问题，或者回应理由站不住的地方。尤其是 Claude **没有采纳**的三处：私人文字不逐段加密（第 1 条）、时钟偏差大的事件照样参与奖励（第 7 条）、ID 前缀暂不自动检查（第 11 条）。
2. **新设计「私人文字」**（事件规格第 4 节）：
   - 删除真的删得掉吗？有没有哪条路径会让文字「复活」，例如离线设备、导入、恢复备份、隔离区、诊断日志？
   - 「文字和引用它的事件放在同一批上传」够不够？设备在两者之间崩溃会怎样？
   - 投影不读文字，这个说法对所有投影都成立吗？
3. **新的选择规则**（事件规格 6.2、7.3）：「排序键最小的候选生效」加上各条规则的「选哪条触发事件」，现在能保证投影只取决于事件集合吗？请尝试找反例，尤其是规则之间有依赖的地方（航线投影 → `task-done`，流水 → `revoke`，申请和目标 → `redeem`）。
4. **语义相等**（事件规格 5.2）：用它判断「重复」，还有误判的情况吗？数值范围的限制，在 Python 和 JavaScript 里真的都能实现、都能检查吗？
5. **引用闭包和引擎等级**（内容规格 3.8、6.1）：有没有漏掉会让发布包断开，或者让旧设备显示不出来的情况？
6. **两份任务提示词**（`prompts/curio-002a.md`、`prompts/curio-003a.md`）：一个没看过仓库的实现 AI 拿到展开后的任务文件，能不能不提问就做对？工作量能不能在一次交付里完成？
7. 修订后的 ADR-002、ADR-004 和领域模型，和两份规格之间还有没有不一致的地方？

不在上面的问题，你觉得重要也请说。

## 输出格式

用简体中文，按下面的格式输出，不要写代码补丁，说清楚问题和建议即可：

```
# 审阅意见 · PR #21 第 2 轮 · 审阅者：<模型名和版本>

## 结论
可以合入 / 改完再合入 / 需要大改（一句话说明）

## 第 1 轮问题的复核
| 第 1 轮编号 | 结论（已解决 / 部分解决 / 未解决 / 不同意回应） | 说明 |
| --- | --- | --- |
| 1 | … | … |
（12 条都要列出）

## 新问题
### 1. <一句话标题>
- 严重程度：阻断 / 重要 / 建议
- 位置：<文件和章节>
- 问题：<具体说明；能举反例的举反例>
- 建议：<怎么改>

### 2. …

## 其他
<不属于具体问题的看法，可以没有>
```

「阻断」只用于：照现在的规格实现出来，会丢数据、算错、泄露隐私，或者以后无法修复的问题。
