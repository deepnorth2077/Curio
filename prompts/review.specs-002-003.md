# 审阅任务：「好奇号」的内容格式规格和事件格式规格

## 背景

「好奇号 Curio」是一个家庭自用的理科探索网站，陪一个孩子从 2026 年小学三年级用到 2036 年高三，覆盖数学、物理、化学、生物。目标是「基础设施级」：数据要用十年，能多设备离线使用、联网同步，能随时换算法重算，任何一点能量、任何一次答题都查得到来历。

仓库只有一个维护者 Claude。其他 AI 只按 Claude 写的任务文件做实现，交付回来由 Claude 审核、整合。Claude 自己写的架构改动不能自己审，所以请你来审。

这次要审的是 PR #21，内容是两份规格，以及一个生成任务文件的小工具。规格合入以后，实现 AI 会**完全照着它们**写 schema 和代码，所以这里的含糊、矛盾和漏洞，都会被原样实现出来。

## 你的角色

资深的数据架构师，熟悉事件溯源、离线优先的多设备同步、内容版本管理和 JSON Schema；同时关心一个三年级孩子实际用起来的情况。请挑刺，不要客气。

## 请重点看这些问题

**内容规格（`docs/specs/content.md`）**

1. 结构化活动的格式，够不够从三年级用到高中？例如高中物理带单位的数值、多空题、表达式、作图题来了，要怎么扩展；现在的设计会不会把路堵死。
2. 内容哈希（第 6.2 节）真的可复现吗？找一找会让两台电脑算出不同哈希的情况（路径排序、Unicode、换行、YAML 和 JSON 的差异等）。
3. 第 5 节的校验规则有没有漏掉重要的一条，或者哪条在 CI 里根本做不到。
4. 提示阶梯「最后一条不能泄露答案」的保守检查，是否会误报得很烦，或者形同虚设。

**事件规格（`docs/specs/events.md`）**

5. 第 5.2 节声称所有投影只取决于事件**集合**，和到达顺序无关。请尝试找反例：构造一组事件，按不同顺序或不同批次到达时，投影或余额会不一样。尤其看航线冲突（5.4）、奖励规则（6.3）、撤销（`reward.revoked` 指向的流水后来消失了）、不一致的尝试（5.3）。
6. 第 9 节对 ADR-004 的五处修订，你是否同意？特别是「奖励流水是投影」和「唯一键改用 `cause_key`」。有没有更简单、同样可靠的做法？
7. 摄入规则（第 4.2 节）：「重复」要求规范 JSON 完全相同，这样严格会不会在实际中误判成「冲突」（例如同一条事件被不同版本的程序序列化）？
8. 隐私：反思、提问这些孩子写的自由文字直接放在事件里，而事件永远不能删（ADR-004 只允许擦除附件）。十年后孩子或家长想删掉某段文字，怎么办？这是否应该现在就改设计？
9. 第一阶段（单设备试用：一个真实知识点、打卡、错题、奖励）要用到的事件，动词表里够不够？有没有多余的？
10. 时间：设备时钟不准时，`activity-done` 规则按本地日期去重、`effective_from` 选规则版本，会不会被钻空子或出错？

**工具和提示词**

11. `tools/make_task.py` 有没有漏洞：会不会生成和提交内容不一致的任务文件、漏报没填的占位符、嵌入的内容提前结束代码块？
12. 两份任务提示词（`prompts/curio-002a.md`、`prompts/curio-003a.md`）：一个没看过仓库的实现 AI 拿到展开后的任务文件，能不能不提问就做对？哪里会让它卡住或做偏？工作量能不能在一次交付里完成？

不在上面的问题，你觉得重要也请说。

## 输出格式

用简体中文，按下面的格式输出，不要写代码补丁，说清楚问题和建议即可：

```
# 审阅意见 · PR #21 · 审阅者：<模型名和版本>

## 结论
可以合入 / 改完再合入 / 需要大改（一句话说明）

## 问题
### 1. <一句话标题>
- 严重程度：阻断 / 重要 / 建议
- 位置：<文件和章节>
- 问题：<具体说明；能举反例的举反例>
- 建议：<怎么改>

### 2. …

## 其他
<不属于具体问题的看法，可以没有>
```

「阻断」只用于：照现在的规格实现出来，会丢数据、算错、或者以后无法修复的问题。
