# 审阅任务：Curio 的 AI 接口（ADR-012 和 `docs/specs/ai.md`）

## 背景

Curio 是一个家庭自用的理科探索网站，陪一个孩子从 2026 年小学三年级用到 2036 年高三，以后可能给几位朋友的家庭各自用。网页是纯前端（ES 模块，不打包），托管在 GitHub Pages；学习记录存在设备上，可以导出加密备份（恢复密钥只有 6 位数字）。活动模块运行在 `sandbox="allow-scripts"` 的 iframe 里，不联网、不碰存储。家长 Luka 不写代码，只负责部署和验收。

原来的设计（ADR-010、`docs/specs/relay.md`）：AI 的密钥只放在每家自己部署的腾讯云云函数里，页面带家庭口令去问它。Luka 觉得部署太繁琐、只能用 DeepSeek、接不了本地模型。2026-11-28 他拍板：

1. 外壳只有一个 AI 接口，背后接法由家长选：直连（OpenAI 兼容，默认 DeepSeek）、本地模型、中转（保留）、自定义。
2. 家长填的密钥只存在设备上，不进备份。
3. 上下文由外壳拼：当前知识点、做到哪一站、猜错过什么、最近几轮对话；活动还没做完时，领航员只给线索、不剧透。

Claude 据此写了 ADR-012 和 `docs/specs/ai.md`，还没有实现。仓库规定：改 `docs/specs/` 的 PR，写的人和审的人要来自不同的模型家族，所以请你来审。

请先读：`docs/adr/0012-ai-interface.md`、`docs/specs/ai.md`；对照着看：`docs/adr/0010-cloud-relay.md`、`docs/specs/relay.md`、`relay/src/navigator.js`、`docs/activity-contract.md`、`docs/specs/backup.md` 第 5 节、`AGENTS.md` 原则 3、5。

## 你的角色

资深前端和安全工程师，熟悉浏览器跨域、混合内容、本地存储、LLM 提示词和儿童产品。请挑刺，不要客气。这个项目只有一个家庭在用、维护者不写代码，所以「部件少、十年后还看得懂」比「灵活」重要。

## 请重点看这些问题

1. **把密钥放在设备的 `localStorage` 里**，对一个家庭自用、预充值很小的场景，风险说清楚了没有？ADR-012「后果」里写的「同一个 github.io 来源下的页面共用本机设置」对不对、全不全？有没有便宜得多的办法明显更好？
2. **只支持一种问法（OpenAI 兼容 `/chat/completions`）**：DeepSeek、国内主流服务、Ollama、LM Studio 是否真的都能用？`extra` 字段（DeepSeek 要关思考）这个做法会不会让别家服务报错？有没有漏掉常见的不兼容点？
3. **出错的翻译**（第 5 节）：浏览器里跨域被拒和网络不通都是 `TypeError`，分不开，这样合并处理对吗？404 和 400 判成 `bad_model` 靠得住吗？家长看到的提示够不够让他自己改对？
4. **iPad 用本地模型**：https 页面调局域网 http 地址，Safari 和 Chrome 现在实际会怎样（混合内容、Private Network Access）？规格第 8 节的预计对不对？有没有不用中转的可行办法？
5. **上下文和揭晓规则**（第 4 节）：「活动没领星卡就只给线索」这一条判断，会不会让领航员在很多正常的问题上也绕圈子、不肯答？措辞（第 4.3 节）有没有让模型误解的地方？上下文里有没有不该发给服务商的东西？
6. **每日次数存在设备上、只在成功时加一**：孩子能不能轻易绕过？这算不算问题（家长的硬上限是预充值）？
7. **中转的新入口**（第 6 节）：忽略客户端的 `model` 和参数、只认 `messages`，这样就不会被拿去当通用的大模型接口白用了吗？16 KiB、2～8 条的限制合理吗？
8. **备份**：「AI 设置不进备份」靠什么保证？测试接缝里那条（在备份包字节里找密钥）够不够？
9. 有没有更简单、部件更少、能达到同样效果的做法？

## 交付格式

一份 Markdown，存为 `docs/reviews/pr-<PR 号>.md`（PR 号以 Luka 给你的为准）：

1. 一句话结论：可以接受 / 改完再接受 / 方向有问题。
2. 编号的意见列表，每条写：在哪（文件和节）、问题、为什么重要、建议怎么改；标「必改」或「建议」。
3. 你不确定、需要实测才能下结论的地方，单独列出来。

不要改 ADR 和规格本身，只写审阅意见；Claude 会逐条处理。
