# 审阅任务：「好奇号」按风险分四档审（ADR-009 增补 1）

## 背景

「好奇号 Curio」是一个家庭自用的理科探索网站，陪一个孩子从 2026 年小学三年级用到 2036 年高三。仓库只有一个维护者 Claude。Luka（家长，不写代码）负责验收、陪孩子试玩、拍板。项目的两条主旨是**审美**和**激发好奇心**。

前六个里程碑里，每件改动不论大小都走同一套审查：外部模型实现，Luka 传话，Claude 收货、两条线审核，再请别的模型审阅。Luka 觉得审查和传话花得太多，但审美和好奇心不能丢。Claude 提出按风险分四档（A 难以撤回、B 科学事实、C 体验和审美、D 其他），内容和模块默认交给 Claude 会话里的子 agent 做，外部模型只用在 A 档审阅和少数跨模型核对上。Luka 已在对话里采纳，按规矩还要请一个不同的模型审阅。这就是你的任务。

## 你的角色

资深工程负责人，也懂儿童教育产品。你熟悉代码审查、测试和风险分级，也明白「一个维护者、几个 AI、家长不写代码」这种协作方式的限制。请挑刺，不要客气。审阅对象是做法本身，不是文字。

## 请重点看这些问题

1. **分档的边界**：哪些改动放错了档？特别是 D 档「CI 通过就合入」里，有没有其实会伤到孩子数据、伤到内容正确性、或者以后很难改回来的东西？「跨几档按最高一档」「拿不准往高放」够不够用？
2. **同一家模型的盲点**：制作、审查、核对都由 Claude 的子 agent 做时，哪类错误最可能一起看漏？「每个学科的第一个知识点用别家模型核对」和「最终关口是孩子试玩」这两条对策够不够？还应该加什么，代价最小？
3. **审美和好奇心**：C 档不再做多模型打分，改为「anatomy 自查 + 另一个子 agent 审查 + 三张截图 + iPad 和孩子试玩」。这样能守住审美吗？有没有更便宜、更可靠的信号（例如孩子的行为数据）应该写进来？
4. **和 ADR-007 的关系**：子 agent 的产出不再用任务文件和收货哈希核对。这和 ADR-007「协作以可校验的任务包为准」冲突吗？增补里「ADR-007 不变，只管经 Luka 传递的交付」的说法站得住吗？还是应该另写一份 ADR-007 的增补？
5. **可追溯性**：子 agent 的工作只留「设计说明 + 审查记录 + 提交署名」，不留哈希。十年后要查「这段内容是谁做的、谁核对过」，够不够？
6. **文档之间有没有矛盾**：增补、`docs/collaboration.md`、`AGENTS.md`、`GLOSSARY.md`、ADR 目录之间，还有没有说法不一致的地方？

## 输出格式

用简体中文，按下面的格式输出，不要写补丁，说清楚问题和建议即可：

```
# 审阅意见 · PR（ADR-009 增补 1）· 审阅者：<模型名和版本>

## 结论
可以合入 / 改完再合入 / 需要大改（一句话说明）

## 问题
### 1. <一句话标题>
- 严重程度：阻断 / 重要 / 建议
- 位置：<文件和章节>
- 问题：<具体说明>
- 建议：<怎么改>

## 其他
<可以没有>
```

「阻断」只用于：照现在的写法执行，会让孩子看到错的内容、丢了孩子的数据，或者以后很难纠正的问题。
